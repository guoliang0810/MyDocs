# 专家作业标准：物理 AI × CAD/CAE 落地（四维版）

> **v4.0（2026-10-26）**：从"三问 + 单维罗列"升级为"**四维交叉**"。
>
> v1 只有产品，v2 补 CAD/技术，v3 补技术路线与竞品——
> 但**四维各自都成立，合起来却常常互相打架**。
> ⭐ **真正的决策不在某一维里，在交叉处。**
>
> **本库的元技能文档。**

> **这是本库 v4 最重要的产出。**

# 一、专家会额外开展哪些我本次没有要求的工作？

## 1.1 通用规律

| # | 专家额外做的事 | 为什么必须做 |
|---|---|---|
| 1 | **反向提问 + 建立问题契约** | 用户的问题通常是模糊的；专家第一件事是把它变成可判定的 |
| 2 | **定义"成功"的度量** | 没有可判定的成功标准，交付就无法验收 |
| 3 | **主动找出"这个问题可能是错的"** | 顶尖专家的第一反应常是"你确定要这么做吗" |
| 4 | **区分"能做的"和"该做的"** | 技术可行 ≠ 商业合理 |
| 5 | **画出失败路径与降级策略** | 专家会问"这个做不成的时候怎么办" |
| 6 | **设定退出机制** | 保护客户，也保护自己不被预期绑架 |
| 7 | **识别可沉淀的资产** | 一次性交付是浪费，沉淀才是复利 |
| 8 | **明确"不做什么"** | 范围控制是交付质量的第一道闸 |

### 技术维度

## 1.3 ⭐ 四维交叉：识别冲突（v4 核心方法）

> **这是本版最重要的新增。** 详见 [[000-四维交叉分析]]。

### 通用识别法

```
① 技术维度：这个技术上能不能做到？做不到的部分是什么？
        ↓
② 用户维度：用户敢不敢用？谁签字？他被什么说服？
        ↓
③ 资方维度：谁付钱？付多少？下一轮谁接？
        ↓
④ 产品维度：能不能复制？复制成本随第几个客户下降吗？
        ↓
⑤ ⭐ 交叉检查：
   · 四维一致 → 直接做（共识点）
   · 两维一致两维冲突 → ⚠️ 选边，并说明牺牲了什么
   · 三维冲突 → ⭐ 重定义问题，而不是选边
   · 有一维明确说"不可能" → 先解决那一维
```

### 三种处理方式

| 冲突形态 | 处理 | 我方实例 |
|---|---|---|
| **两两冲突** | 选边 + 明确说出牺牲了哪一维 | "主攻几何前处理" = 牺牲了"技术最性感"的叙事 |
| **三维冲突** | ⭐ **重定义问题** | "AI 替代求解器" → "**AI 把 CAE 的迭代速度提升一个数量级**"（四维全部受益） |
| **一维否决** | 先解决那一维，其余暂停 | 军工场景：**保密资质/编校审批**不过，其他都白说 |

# 二、专家会使用的原始一手素材？

> ⭐ **判断标准只有一条：你能打开原始文件，看到未经转述的事实吗？**

## 2.1 通用类别

| 类别 | 是什么 | 为什么专家直接用 |
|---|---|---|
| **原始文献全文** | 论文 PDF / 预印本原文 | 摘要会骗人，方法与数据不会 |
| **标准正文 + 生命周期页** | 标准组织正式文本 | 解读文章常漏条款号与版本状态 |
| **原始数据集** | 数据文件 + 数据卡 | 论文里的图是二次加工 |
| **⭐ 用户原话与一手语料** | 论坛/知乎/招标文件/读者来信/社群 | ⭐ **二手转述会抹掉犹豫与分歧** |

| **官方 release notes** | 版本变更记录 | 产品生命周期的唯一权威 |

# 三、专家会用到的研究方法、分析手段与专业工具？

## 3.1 研究方法

| 层级 | 方法 |
|---|---|
| **数值方法** | FEM / FVM / FDM / SPH / DEM / 粒子法 |
| **降阶与加速** | ROM / POD / 代理模型 / 神经算子 |
| **不确定性** | UQ（NeuralUQ、UQNO）、贝叶斯优化、DoE（LHS）、参数辨识/反问题 |
| **敏感性分析** | ⭐ **SALib**（Sobol、Morris、FAST、RBD-FAST、Shapley Effects） |
| **验证确认** | 代码验证 / 结果确认 / **GCI** / **盲预测** |
| **多保真融合** | 高保真试验 + 低保真仿真 + 代理模型 |
| **几何拓扑** | 亏格 / 欧拉数 / **Betti 数** / Manifold 性 / 几何哈希 / 拓扑不变网络架构 / 等变操作 / 神经隐式表示 |
| **⭐ 路线评估方法** | 成熟度分级 / 八条短路硬判据 / 四栏成本结构 / 失败模式归因 / 机构押注矩阵 |
| **⭐ 竞品研究方法** | 财务穿透（收入结构/研发占比/应收周转/季度集中度/毛利率归因）、中标金额分档统计、候选人排名分析、量化指标可核验性四级分类、收购与生态站位追踪、对手自曝证据挖掘 |
| ⭐ **用户研究方法** | **岗位 JD 文本挖掘**（能力分层与薪资分层）、**采纳关卡建模**（G0–G9）、**信任机制识别**（三种）、**语料分析**（用户黑话 vs 厂商话术）、**采购制度文本分析**（金额触发点与审批层级）、**Gatekeeper 识别** |
| ⭐ **资方研究方法** | **估值坐标定位**（L1–L4）、**溢价来源拆解**、**政策变量追踪**（国办发〔2025〕1 号）、**投资组合反推偏好**（哈勃工商变更）、**可比公司财务镜像**（PS/研发占比/应收周转）、**并购倍数对标**（14× 收入）、**信号性质甄别**（意向 vs 事实） |
| **⭐ 交叉分析方法** | **四维冲突矩阵**、**共识点/决策点分离**、**冲突形态分类**（两两/三维/一维否决）、**重定义问题法** |
| **产品侧** | 约束收集、问题契约、DoE 覆盖矩阵、PoC 门槛设计、FMEA、5 Whys、意图丢失量化实验 |

## 3.2 分析手段

| 环节 | 动作 | 判据/工具 |
|---|---|---|

# 五、⭐ 落地为默认流程：核验清单（20 项）

> **本轮最贵的一课：18 个编号错 9 个、1 个标准号写错、2 个产品分类错误、
> 3 个竞品不存在、1 个对标对象搞错、5 个资本信号无一构成股权变更。**
> 成本极低，收益极高——固化成流程。

### 强制流程

> **每条 arXiv / 标准号 / 算例名 / 价格 / 产品名 / 开源分类 / 技术路线成熟度 /
> 竞品财务数字 / 用户分层数据 / 融资事件 / 估值数字，
> 必须经过"打开原始页面确认"这一步。未核实一律标 `⚠️未核实`。**

### 清单

**技术与引用（9）**
- [ ] 论文 abs 页核对**标题**与**作者**
- [ ] 论文 Comments 确认是否已发表
- [ ] 论文查是否**有同名论文**
- [ ] ⭐ 论文看**有没有 OOD 实验章节**（判断路线成熟度）
- [ ] ⭐ 论文读**自陈局限**
- [ ] 标准查**标准号 + 版本年份 + 现行/已撤销状态**
- [ ] 标准查是否**分部分**、是否在修订中
- [ ] 开源库查**最后推送日期**与 **LICENSE 实际内容**
- [ ] 许可证确认**商用是否受限**

**产品与市场（4）**
- [ ] 价格回**原始公告页**核对金额、日期、规格、并发数
- [ ] 产品查**官方 release notes** 确认生命周期
- [ ] 产品确认**商业 vs 开源**，读定价页
- [ ] 数据集检查**版本号与 DOI**

**竞品与财务（3）**
- [ ] ⭐ 财务数字是否来自**上市公司公告**而非媒体转述？口径是否标注？
- [ ] ⭐ 中标数字是否来自**原始公告**？候选人排名是否核实？
- [ ] ⭐ 竞品宣传数字属 **🅐/🅑/🅒/🅓 哪一级**？🅒 是否标注了自证循环？
