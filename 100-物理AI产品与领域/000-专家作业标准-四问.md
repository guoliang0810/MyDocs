# 专家作业标准：四问

> **这份文档是本库的"元技能"。**
> 它不记录某个具体知识，而是记录：
> **面对任何一个陌生领域的同类问题，顶尖专家会多做什么、拿什么原始素材、用什么方法、怎么被独立验证。**
>
> 以后遇到新的领域、新的任务，先按这四问走一遍，再动手。

---

## 零、为什么要有这份文档

清航飞迈所处的物理 AI 领域有一个致命特征：
**这个领域的错误往往是"看起来很合理"的。**

真实案例（本次重构中实测）：

| 错误类型 | 表现 | 后果 |
|---|---|---|
| **编号幻觉** | 4 个看起来专业的 arXiv 编号里 **3 个指向完全无关的论文** | 技术评审中当场暴露 |
| **产品名幻觉** | "Assistants API v3 (2026)" —— 该版本不存在，该 API 已于 2026-08-26 关停 | 文档失去可信度 |
| **版本幻觉** | "AutoGen 2.0" —— 从未存在过 | 选型结论被推翻 |
| **时间错挂** | 把 2024-09 的 o1 当作"2026 趋势"的锚点 | 整篇分析的时间基准错位 |
| **概念包装** | 把 GitHub 仓库包装成"带正式标题的论文" | 不可溯源 = 不可核验 |
| **精度通胀** | "仿真速度提升 80%" 无法给出基准算例、网格规模、精度等效性证明 | 客户一追问就崩 |

> ⭐ **所以这个领域的"专家作业标准"不只是更严谨，而是生存必需。**
> **任何一个没打开原始页面核实过的编号，都是一颗定时炸弹。**

## 一、问：专家会额外开展哪些我本次没有要求的工作？

> **这是四问中最容易被跳过、但价值最高的一问。**
> 你要求的是"回答问题"，专家做的是"**先把问题定义对**"。

### 1.1 通用规律（跨领域通用）

| # | 专家额外做的事 | 为什么必须做 |
|---|---|---|
| 1 | **反向提问 + 建立问题契约** | 用户的问题通常是模糊的。专家第一件事是把它变成可判定的 |
| 2 | **定义"成功"的度量** | 没有可判定的成功标准，交付就无法验收 |
| 3 | **主动找出"这个问题可能是错的"** | 顶尖专家的第一反应常是"你确定要这么做吗" |
| 4 | **区分"能做的"和"该做的"** | 技术可行 ≠ 商业合理 |
| 5 | **画出失败路径与降级策略** | 专家会问"这个做不成的时候怎么办" |
| 6 | **设定退出机制** | 保护客户，也保护自己不被预期绑架 |
| 7 | **识别可沉淀的资产** | 一次性交付是浪费，沉淀才是复利 |
| 8 | **明确"不做什么"** | 范围控制是交付质量的第一道闸 |

## 二、问：专家会用哪些原始一手素材？

> **核心区分**：
> - **二手材料** = 别人加工整理好的结论（新闻稿、综述、博客、课件、笔记）
> - **一手素材** = **原始来源本身**，可被独立打开、独立核验

> ⭐ **判断标准只有一条：你能打开原始文件，看到未经转述的事实吗？**

### 2.1 通用的一手素材类别

| 类别 | 是什么 | 为什么专家直接用 |
|---|---|---|
| **原始文献全文** | 论文 PDF / 预印本原文 | 摘要会骗人，方法与数据不会 |
| **标准正文** | 标准组织的正式文本（不是解读文章） | 解读文章常漏条款号 |
| **原始数据集** | 数据文件本身 + 数据卡 | 论文里的图是二次加工 |
| **原始日志/工单/邮件** | 一手的现场记录 | 复盘的唯一真相来源 |
| **招标与采购公告原文** | 政府采购网公告 | 中标公告 = 真实成交价，二手转述常错 |
| **官方 release notes** | 版本变更记录 | 产品生命周期的唯一权威 |
| **一手访谈/会议纪要** | 原始录音与逐字记录 | 二手总结丢掉了犹豫和分歧 |
| **代码仓库提交历史** | git log | 变更时间线与真实演进过程 |

## 三、问：专家会用哪些研究方法、分析手段与专业工具？

### 3.1 研究方法

| 层级 | 方法 |
|---|---|
| **数值方法** | FEM / FVM / FDM / SPH / DEM / 粒子法 |
| **降阶与加速** | ROM / POD / 代理模型 / 神经算子（FNO、DeepONet） |
| **不确定性** | UQ（NeuralUQ、UQNO）、贝叶斯优化、DoE（LHS）、参数辨识/反问题 |
| **敏感性分析** | ⭐ **SALib**（Sobol、Morris、FAST、RBD-FAST、Delta Moment-Independent、Shapley Effects） |
| **验证确认** | 代码验证（Verification）/ 结果确认（Validation）/ **GCI 网格无关性** |
| **多保真融合** | 高保真试验 + 低保真仿真 + 代理模型 |
| **产品侧** | 约束收集、问题契约、DoE 覆盖矩阵、PoC 门槛设计、FMEA、5 Whys、失败模式与影响分析 |

### 3.2 分析手段（最实用的部分）

| 环节 | 具体动作 | 判据/工具 |
|---|---|---|
| **网格划分与质量** | 长宽比、扭曲角、雅可比、单元类型匹配、**相邻尺寸比 ≤1:3**、应力集中处 ≤特征尺寸 1/10 | GB/T 33582-2017；`checkMesh`（OpenFOAM） |
| **边界条件策略** | 硬/软约束、对称与周期简化、约束 DOF 正确性；**BC 分布外推是神经算子最大失效源** | `2601.11428` |
| **材料本构** | 各向异性（尤其复材）、温度相关、率相关、损伤起始与演化 | GB/T 33582 |
| **收敛判据** | ①迭代收敛 ②网格收敛（GCI）③时间步收敛 ④观测量历史收敛曲线 | DPW-6 要求提交迭代收敛信息 |
| **结果判读** | 奇异点识别、**热点强度与位置分离**、能量平衡校验、与试验/解析解对比 | PyVista / ParaView / DPF |
| **谱误差诊断** | 傅里叶模态误差分布 | `2601.11428` |
| **误差分解** | ⭐ **分离高保真离散化误差与学习引入误差** | FSU S. Lee 课题组方法学 |
| **FMEA** | RPN = S×O×D；**对"求解不收敛"本身做 FMEA** | —— |
| **因果分析** | 不止相关性——Sobol/Morris/Shapley 区分"真驱动"与"共变" | SALib |

## 四、问：独立于你、我之外，怎么核验结论正确？

> **这是四问中最后一问，也是把"我的判断"变成"可验证事实"的一步。**

### 4.1 核验的三个层次

| 层次 | 核验什么 | 渠道 |
|---|---|---|
| **L1 存在性** | 这个编号/产品/标准/价格**真的存在吗** | arXiv abs 页、官方产品页、标准组织主页、政府采购网原公告 |
| **L2 准确性** | 我说的**属性和数字对吗** | 官方 release notes、标准正文、原始公告页、PDF 原文 |
| **L3 有效性** | 它**真的能支撑我的结论吗** | 第三方独立基准、盲预测、同行评议、复现 |

### 4.2 具体核验渠道

#### 🔍 存在性与准确性

| 渠道 | 用法 | 本次实测收获 |
|---|---|---|
| **arXiv abs 页直查** | ⭐ **最高效的证伪工具**：`arxiv.org/abs/<ID>`，核对标题与作者 | ✅ **抓出 4 个编号中 3 个指向完全无关的论文** |

## 五、⭐ 落地为默认流程：编号核验清单

> **本次最贵的一课：调研 4 个论文编号，3 个是错的。**
> 成本极低，收益极高——把它固化成流程。

### 强制流程

> **知识库中每条 arXiv / 标准号 / 算例名 / 价格 / 产品名，必须经过"打开原始页面确认"这一步。**
> 未核实的一律标 `⚠️未核实`，**不许凭记忆写编号。**

### 核验清单（逐条过）

- [ ] **论文**：打开 `arxiv.org/abs/<ID>`，核对**标题**与**作者**（不只是编号存在）
- [ ] **论文**：看 Comments 字段确认是否已发表（避免引用未评审预印本）
- [ ] **论文**：看 GitHub 仓库是否有 `models/`、`data/`、复现脚本
- [ ] **标准**：在标准组织主页核对**标准号 + 版本年份 + 现行状态 + 管辖范围**
- [ ] **价格**：回到**原始公告页**核对金额、日期、规格、并发数
- [ ] **产品**：查**官方 release notes / changelog**，确认功能与生命周期
- [ ] **数据**：检查数据集的**版本号与 DOI**（v2 与 v3 可能内容不同）
- [ ] **基准**：确认基准的**已知解/真值带**，而不是只看算例名

### 标注规范

| 标记 | 含义 |
|---|---|
| ✅ | 已打开原始页面核实，标题/作者/数字均已确认 |
| ⚠️ | 二手来源，**使用前需复核**（并写明复核入口） |
| ❌ | 已核实为错误/不存在，**仅作反例保留** |
