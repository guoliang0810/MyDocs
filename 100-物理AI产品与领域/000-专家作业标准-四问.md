# 专家作业标准：物理 AI × CAD/CAE 落地

> **v3.0（2026-10-26）**：新增**技术路线分析**与**竞品分析**两个维度。
> v2 补上了 CAD/几何侧，v3 补上"**哪条技术路线**"与"**跟谁竞争**"——
> 这两个是产品负责人与 FDE 最难自己长出来、也最容易出错的判断。
>
> **本库的元技能文档。** 不记录某个具体知识，而是记录：
> **面对物理 AI × CAD/CAE 落地的任何一个同类问题，顶尖专家会多做什么、拿什么原始素材、用什么方法、怎么被独立验证。**

## 零、这个领域的三类致命错误

> **本轮研究实测（全部有据可查）：**

| 类别 | 实例 | 后果 |
|---|---|---|
| **① 编号幻觉** | ⭐ **18 个 arXiv 编号中 9 个被证伪**——包括我最初凭记忆写的 4 个，和提问时给出的 4 个 | 技术评审当场暴露 |
| **② 路线错位** | ⭐ **把"物理 AI"当成一个东西** —— 实际是 6 条主线 24 条子路线，成熟度从"研究"到"可交付"跨 4 档 | 选错路线，投入全废 |
| **③ 可执行 = 正确** | Text2CAD-Bench：领域模型 **IR 低至 2%，但 CD ≈ 220、IoU ≈ 0** | 几何完全不对但看起来一切正常 |

### ⭐ 加上竞品侧的第四类

| 类别 | 实例 | 后果 |
|---|---|---|
| **④ 叙事错位** | ⭐ **把清航飞迈对标 PhysicsX** —— 但 AICube（物理直觉+神经算子+全栈自研+行业闭环）国际可比对象其实是 **51WORLD** | 投资人按错误的估值锚给价 |

# 一、专家会额外开展哪些我本次没有要求的工作？

## 1.1 通用规律

| # | 专家额外做的事 | 为什么必须做 |
|---|---|---|
| 1 | **反向提问 + 建立问题契约** | 用户的问题通常是模糊的；专家第一件事是把它变成可判定的 |
| 2 | **定义"成功"的度量** | 没有可判定的成功标准，交付就无法验收 |
| 3 | **主动找出"这个问题可能是错的"** | 顶尖专家的第一反应常是"你确定要这么做吗" |
| 4 | **区分"能做的"和"该做的"** | 技术可行 ≠ 商业合理 |
| 5 | **画出失败路径与降级策略** | 专家会问"这个做不成的时候怎么办" |
| 6 | **设定退出机制** | 保护客户，也保护自己不被预期绑架 |
| 7 | **识别可沉淀的资产** | 一次性交付是浪费，沉淀才是复利 |
| 8 | **明确"不做什么"** | 范围控制是交付质量的第一道闸 |

## 1.2 ⭐ v3 新增：⭐ 技术路线层面的额外工作

> **这是产品负责人最需要、也最容易漏的一层。**
> 不做路线判定的专家，会把"能做"的技术当成"该做"的技术。

| # | 专家额外做的事 | 具体内容 |
|---|---|---|
| **1** | ⭐ **先把"物理 AI"拆成路线，而不是当成一个东西** | 6 主线 24 子路线（A 代理模型 / B 求解器 AI 化 / C AI for 建模 / D LLM 驱动 / E 混合与工程化 / F 评测基础设施），每条给成熟度：研究 / 试点 / 可交付（辅助）/ 可交付（自主） |
| **2** | ⭐ **用可判定的硬判据选路线，而不是靠感觉** | 八条短路判据 J1–J8（是否需认证签字 / 有无 30–50 个已收敛算例 / 是否离开训练分布 / 是否需长时间外推 / 瓶颈在代数还是几何 / 几何可否参数化 / 网格规模 / 是否原子尺度）→ 见 [[物理AI技术路线全景#二-路线选择的八条硬判据]] |
| **3** | ⭐ **算成本结构，而不是只算技术可行性** | 训练/推理/一次性工程/数据四栏成本；**A2 是"训练成本换推理成本"，E3 是唯一"训练成本≈0"的可交付路线**（因为复用客户已付过钱的仿真数据） |
| **4** | ⭐ **认失败模式，而不是只认成功案例** | 外推失效（A2）、训练比求解更贵（A3）、系统性 PES 软化（C5）、语法可以物理不行（D）、前后生态割裂（C3） |
| **5** | ⭐ **识别"当前的行业天花板"** | ⭐ **目前没有任何一条路线达到"可交付（自主）"**——所有厂商都把 AI 定位为**筛选器**而非**签字者**。这是市场现状，不是我们的短板 |
| **6** | ⭐ **区分"真差异化"与"伪差异化"** | 真：AI 替代**物理场求解**本身（正交于 SimSolid 的"替代网格"）、复材层合板本构+变刚度、医疗骨科完整链路。伪：能导入 STEP、有 AI 助手、能浏览器跑、几何深度学习领先、快 80% |
| **7** | ⭐ **认"最务实但最不性感"的那条路** | E3（AI-in-the-loop）：训练成本≈0、符合认证现实、所有巨头都自发走这条路——但价值叙事依附宿主软件，看起来像"功能增强"而非"新范式"，资本市场给 E3 的定价远低于其现金流贡献 |

## 1.4 ⭐ 链路环节展开（沿用 v2，补充 CAD 侧）

### 环节 A：前期——几何是第一道闸

| 专家额外做的事 | 具体内容 |
|---|---|
| **几何缺陷成本量化** | 3 个小面 + 1 条小缝 → 最小面面积比小 5 个数量级 → 单元数 2×、核时 4× |
| **入口预检规则** | 自相交 / 非流形 / 短边 / 小面 / 缝隙 / 尖角 |
| **几何清理优先级** | 缝合容差**逐步增大**；小特征阈值 **< 全局网格尺寸 1/5** |
| **defeature 的影响量化** | 双向 Hausdorff + 体积/面积守恒 |
| **DFMA 前置** | C919 复材机翼公开材料明确采用"面向制造装配的设计（DFMA）理念" |
| **⭐ 把"不能"做成合法交付物** | 在航空/医疗场景，基于不可信模型的减重承诺直接导致适航/临床风险 |

### 环节 B：建模——网格质量三档基线

三档阈值表（长宽比、偏斜度、雅可比、翘曲、锥度、内角、正交质量、形状因子）+
**不同求解器口径差异**（ANSYS Orthogonal Quality vs Abaqus Jacobian）+ 渐进式划分 + **云图叠加网格质量云图** + 网格收敛 <1–2%。

### 环节 C：⭐ 代理模型——"可执行 ≠ 正确"的镜像陷阱

| 陷阱 | 表现 | 判官 |
|---|---|---|
| **代码可执行 ≠ 几何正确** | IR 2% 但 CD ≈ 220、IoU ≈ 0 | ⭐ **几何内核** |
| **模型能跑 ≠ 物理可信** | 训练域外误差放大 6×（BC）/ 3.9×（强非线性） | ⭐ **基准 + 试验** |

**几何侧六层验证**：可执行 → B-rep 有效 → 水密 → 流形可网格化 → 量守恒 → 拓扑不变量（Betti 数/欧拉数/亏格）

### 环节 D：验证——三个层次的证据

存在性（arXiv abs 页、ISO 目录页、官方 release notes、政府采购网原公告、GitHub API）→
准确性（标准正文、原始公告、官方文档、LICENSE）→
**有效性（NAFEMS 基准 / 盲预测 / 几何内核 / 独立软件交叉比对）**

### 环节 E：意图传递——CAD→CAE 丢了多少

**往返实验**：原生 CAD → 中性格式 → 回到另一 CAD/CAE，比对装配层数、材料指派、基准体系、**PMI 语义（不是图形）**、Validation Properties、运动副。
**硬机制**：Persistent ID（CAx-IF v1.8）——STEP `V5_UUID_ATTRIBUTE` ↔ QIF `EntityExternalIds`，正确实施可达 **100% 可追溯**；CAx-IF R57J **STEP 数据交换成功率 97%**。

### 环节 F：交付——证据包与责任边界

结果血缘包（求解器版本/网格/输入卡/材料卡/边界条件/求解日志/GCI/迭代收敛历史/权重 hash/后处理脚本/假设清单）+
**证据等级声明**（L-1 方案比选 / L-2 设计输入 / L-3 符合性证据）+ 三层签署链 + 失败工况记录。

### 环节 G：复盘与产品化沉淀

结构化复盘写入 PRD + **未沉淀资产清单** + FMEA + **L1–L4 四层沉淀** +
⭐ **CI 化 V&V**（每次求解器/算法变更自动跑 NAFEMS 基准 + 自有回归集，GCI 或对标偏差超阈值则**阻断合并**）。

# 三、专家会用到的研究方法、分析手段与专业工具？

## 3.1 研究方法

| 层级 | 方法 |
|---|---|
| **数值方法** | FEM / FVM / FDM / SPH / DEM / 粒子法 |
| **降阶与加速** | ROM / POD / 代理模型 / 神经算子 |

# 五、⭐ 落地为默认流程：核验清单（14 项）

> **本轮最贵的一课：18 个编号错 9 个、1 个标准号写错、2 个产品分类错误、1 个对标对象搞错。**
> 成本极低，收益极高——固化成流程。

### 强制流程

> **每条 arXiv / 标准号 / 算例名 / 价格 / 产品名 / 开源分类 / 技术路线成熟度 / 竞品财务数字，
> 必须经过"打开原始页面确认"这一步。未核实一律标 `⚠️未核实`。**

### 清单

- [ ] **论文**：打开 abs 页核对**标题**与**作者**
- [ ] **论文**：看 Comments 确认是否已发表
- [ ] **论文**：查是否**有同名论文**
- [ ] **论文**：⭐ **看有没有 OOD 实验章节**（判断路线成熟度）
- [ ] **论文**：⭐ **读自陈局限**（Causal PINN 那样诚实承认的才有价值）
- [ ] **标准**：查目录页，核对**标准号 + 版本年份 + 现行/已撤销状态**
- [ ] **标准**：查是否分部分（JT 是 14306-1/2/3/4）
- [ ] **标准**：查是否在修订中（ISO/DIS、ISO/CD）
- [ ] **价格**：回原始公告页核对金额、日期、规格、并发数
- [ ] **产品**：查官方 release notes / changelog 确认生命周期
- [ ] **产品**：确认商业 vs 开源，读定价页与 License
- [ ] **开源库**：用 GitHub API 查**最后推送日期**与 **LICENSE 实际内容**
- [ ] **数据**：检查版本号与 DOI
- [ ] **基准**：确认已知解/真值带
- [ ] **许可证**：确认商用是否受限（AGPL / GPL 静态链接 / 双许可）
- [ ] ⭐ **竞品财务**：数字是否来自**上市公司公告**而非媒体转述？口径是否标注？
- [ ] ⭐ **竞品宣传数字**：属于 A/B/C/D 哪一级可核验性？C 级是否标注了自证循环？

### 标注规范

| 标记 | 含义 |
|---|---|
| ✅ | 已打开原始页面核实，标题/作者/数字/状态均已确认 |
| ⚠️ | 二手来源，**使用前需复核**（并写明复核入口） |
| ❌ | 已核实为错误/不存在，**仅作反例保留** |
