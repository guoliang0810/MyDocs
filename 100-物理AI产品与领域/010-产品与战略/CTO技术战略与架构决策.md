### 1.2 物理约束 GPINO：自研 vs 用现成的成本账

#### 1.2.1 BP 的主张应被如何理解

BP 称"物理约束 GPINO 模型（解耦几何与物理场表征）"，学术原型是 **GINO（Geometry-Informed Neural Operator）**：

| GINO 关键设计 | 原文（✅ 已核实） | 对 FEMAI 的含义 |
|---|---|---|
| 三段式架构 | 几何编码器（多层 GNO 局部核积分）→ 全局模型（FNO 层）→ 几何解码器（GNO） | BP 的"解耦几何与物理场表征"= GINO 的 **Encoder/Decoder 与 Global Model 分离** ✅ **描述准确** |
| 几何表示 | SDF + 表面点云 | 与 FEMAI-LEGO 的几何解析天然衔接 |
| **离散化收敛性** | 训练后可用于任意离散化；实测**零样本超分辨率**（1/8 网格点训练） | ✅ **这是神经算子相对 CNN/UNet 的核心优势，也是 BP 该技术主张的真正价值点** |
| 训练数据量 | 仅 **500 个样本**即学到表面压力场 | → 代理模型的边际成本主要在**数据生产**而非模型训练 |
| 加速比 | 阻力系数计算比 GPU 版 OpenFOAM 快 **26,000×** | ⚠️ 表面压力场景，**不能直接迁移到 3D 接触/装配** |
| 精度 | Ahmed-body **8.31%**、Shape-Net **7.29%**；对比 MeshGraphNet 13.88%、FNO 12.59% | ⚠️ 与 BP 的 −73%~+13% **量级完全不同** |

来源：[arXiv:2309.00583](https://arxiv.org/abs/2309.00583)

#### 1.2.2 ⭐ 成本对照（这是最有说服力的一张表）

`neuraloperator` 库（MIT）的实际文件规模（GitHub API 2026-10-27 查询）：

| 文件 | 字节 | 对应能力 |
|---|---|---|
| `neuralop/models/gino.py` | **25,146** | GINO 完整实现（几何编解码 + FNO 全局模型 + SDF） |
| `neuralop/models/fnogno.py` | **17,944** | FNOGNO：正则网格 → 任意查询点云（"几何与物理场解耦"的官方实现） |
| `neuralop/models/fno.py` | 22,803 | FNO 基座 |
| `neuralop/models/codano.py` | 28,005 | CoDANO：协方差感知算子学习（直接给不确定度） |
| **`neuralop/models/uqno.py`** | **2,090** | **UQNO：共形预测校准的不确定性量化** ← 替代"96.8%"的正解 |

| 工作项 | 自研（人月） | 基于 `neuraloperator`（人月） | 差额 | 建议 |
|---|---|---|---|---|
| GINO 架构复现 | 12–18 | **1–2** | 10–16 | ❌ **不自研** |
| 物理约束 loss（PDE 残差 + BC） | 6–10 | 3–5 | 3–5 | 🟡 半自研（**残差定义是我方知识壁垒**） |
| 可微邻域（mGNO 式 mollifier） | 8–12 | 2–3（照搬 arXiv:2504.08277） | 6–9 | 🟡 抄方法不自研 |
| **接触/装配的算子定义** | **15–25** | 15–25（**无现成可抄**） | **0** | ✅ **必须自研 ← 真正的护城河** |
| 不确定性量化 | 4–6 | **0.5**（UQNO + 共形预测） | 3.5–5.5 | ❌ 不自研 |
| GPU/昇腾算子优化与部署 | 8–12 | 4–6 | 4–6 | 🟡 折中 |
| **合计** | **53–83** | **26–46** | **27–37** | |

⭐ **结论**：**自研 GINO 架构本身是净负价值**（多花 27–37 人月且不产生差异化）。
真正不可替代的只有一块：**接触/装配/多体域的算子化定义与几何语义**——因为学术前沿在此处**确实是空白**。

#### 1.2.3 必须澄清的三点

| 维度 | GINO（arXiv:2309.00583） | 物理约束版（mGNO / πG-Sp²GNO） | FEMAI 应有位置 |
|---|---|---|---|
| **导数计算** | 原始 GINO **不支持**物理损失（因 GNO 硬指示邻域不可微） | mGNO 用 mollifier 平滑邻域 → 支持 Autograd 精确梯度（[arXiv:2504.08277](https://arxiv.org/abs/2504.08277), TMLR 2025 ✅） | **必须走 mGNO 路线**，否则物理约束只是形式上的 |
| 训练范式 | 纯监督（500 样本） | 物理损失 + 数据混合 | 有真实求解器数据 → **纯监督 + 物理损失辅助**混合 |
| **域外泛化** | 几何变化时可靠 | 需域分解迭代 | ⭐ **接触问题的域外泛化是核心难点**：新接触位置/新装配关系 = 训练分布外 |

#### 1.3.3 ⭐⭐ 接触问题下预条件器会失效的 4 条机理

| # | 机理 | 细节 | 后果 |
|---|---|---|---|
| **M1（最致命）** | **互补条件不是线性方程组** | 接触的数学本质是 KKT/变分不等式：间隙 g≥0、拉格朗日乘子 λ≥0、互补条件 g·λ=0。Krylov 方法（FCG/GMRES）的基本前提是线性 +（半）正定 | "学习预条件子 + Krylov"路线**在数学上不适用** |
| **M2** | **算子不连续 → 违反神经算子基本假设** | 接触面"开/闭"与"粘/滑"状态切换是**离散跳变**；GNO 的硬指示邻域本身已不可微 | 模型在接触激活边界附近外推**完全失效**；梯度不可用 |
| **M3** | **近奇异谱 + 局部化的接触压力场** | 接触激活后系统矩阵最小特征值 → 0（近奇异）；接触压力场高维、空间局部化，低秩 ROM 无法准确表示 | 粗空间在未接触区域无信息；接触区域迭代不收敛 |
| **M4** | **摩擦导致多值与历史相关** | stick-slip 分岔使"接触力–位移"关系非单调；同一几何+载荷 → 不同历史路径 → 不同输出 | **违反算子的单值性；纯前馈代理原理上不可解** |

⭐⭐ **警示文献（最重要的一篇）**：
[arXiv:2608.02036](https://arxiv.org/abs/2608.02036) 指出——
把神经算子单元从固定几何扩展到**几何参数化**会**导致 Hessian 非定、Newton 收敛到伪极小（误差 247%）**，
需凸神经能量单元修正，才达 **0.6–1.0% L2、3D 0.23%**。

> ⭐ **这正是"神经算子 + 自研非线性有限元求解器"架构选择的核心警示文献。**
> **必须回答"若接触状态发生切换，预条件器还成立吗"** —— 这正是 247% 误差的成因。

#### 1.3.4 ⭐ 把"接触力代理"改写为 4 个可解的子问题

| 方案 | 学习对象 | 为什么可行 | 可复用 |
|---|---|---|---|
| **S1 接触检测代理**（推荐主线）| **间隙函数 g(x)**、接触区掩码、峰值位置 | g 是**连续函数**（非互补条件）；训练时用 CCD **必要+充分条件**作物理正则 | 方法论照搬 [2507.13459](https://arxiv.org/abs/2507.13459)；GNN 骨架用 `neuraloperator` 的 GPU hash-table 邻域搜索 |
| **S2 低维接触力代理** | 接触法向合力、法向力矩、接触面积、峰值压强 | **标量/低维输出**规避高维局部化难题；工程上客户真正要的多为合力与应力极值 | UQNO / CoDANO 做不确定度 |
| **S3 学习作初值 + 主动集求解** | 学习模型给**初值/接触集猜测**，自研求解器完成 Newton/罚函数迭代 | 把学习误差放在**预条件子（可迭代纠正）**而非**解（不可纠正）**上 | 所有已核实预条件子论文的共同范式 |
| **S4 物理约束 loss** | 不可穿透惩罚、λ≥0、互补残差、能量守恒残差 | 直接对应 M1–M4 | mGNO 路线（[2504.08277](https://arxiv.org/abs/2504.08277)） |

⭐ **CTO 决策建议**：
> 把"神经算子预条件器"降级为**内部工程手段**（可随时替换、无对外品牌价值），
> 把对外技术品牌迁移到 **"几何语义 + 物理场联合表征 + 接触/装配领域知识"**——
> 因为这是唯一有学术空白、且竞品（NVIDIA / Ansys / PhysicsX / 飞捷科思）尚未占据的位置。

#### 1.4.3 技术栈选择：不要自研几何内核，但要抢 IR 层

| 层 | 选型 | 理由 |

### 2.3 ⭐⭐ "神经算子 + 接触"的第一个可信证据：完整实验设计

#### 算例选择（三级递进）

#### ⭐ 预注册的可否证结论（启动前必须签字）

> **H1**：接触激活/脱开边界被显式覆盖时，S1+S2 组合可在未见几何族上把峰值应力误差压到 ≤15%，最大穿透 ≤1e-3 网格尺度
> **H2**：S3（学习初值 + 主动集迭代）可把接触求解的 Newton 迭代数降低 ≥50%，最终解偏差 ≤1e-6 —— **这是唯一能支撑"预条件器"对外表述的证据形式**
> **H3（否证）**：若 B5（ROM/SVD）已足够好，说明该问题不需要代理模型 → 资源全部转向 S1/S2 与 IR 层
> **H4（否证）**：若 B3→B4 消融未显示显著增益，说明接触空白点的技术假设本身需重新审视

⭐ **"否证同样是战略结论"** —— 但**必须在启动前签字**，不能在结果出来后解释。

### 3.2 ⭐ 推荐架构：**⑤ 的严格变体**

```
┌──────────────────────────────────────────────────────────────┐
│  L4 交付层：Loopaxis 工作盒 / 在线平台（Triton + IGX Thor）      │
│      ▲ 只吃 ONNX + 自有 IR，不含任何 GPL 代码                 │

│      + 接触子代理(S1/S2) + UQNO 共形预测 + 区间验证             │
├──────────────────────────────────────────────────────────────┤
```

**5 条理由**：

| # | 理由 | 支撑事实 |
|---|---|---|
| R1 | **精度风险被隔离在 L1 地基**，AI 层只做"加速"不做"背锅" | 唯一能同时满足"AI 加速"与"结果可交付"的架构 |
| R2 | **20 人的产能必须集中在 2 个稀缺层** | L3 几何语义 + L2 代理 ≈ 8–10 人；L1 薄求解器 2–3 人；其余 6–8 人做基础设施/交付/应用 |

| R4 | ⭐ **自研求解器的角色从"性能竞争"转为"数据引擎"** | 通用求解器不输出代理训练真正需要的量（伴随梯度 ∂J/∂x、接触反力**历史**、界面热流分量、几何梯度 ∂field/∂mesh）。**自研求解器若能输出这些，就是不可替代的数据资产。这条路径不需要打败 Fluent** |
| R5 | **赛道已有验证者** | PhysicsX（150+ 人、$155M+ 融资、估值约 $24 亿）走的就是"AI 多物理推理 + 数值求解器结合" |

| 维度 | 影响 | 应对 |

| **HDF5** | CGNS 底层 | ✅ 训练中间张量与元数据 |
| **Zarr** | 分块 n 维数组，**原生支持云对象存储** | ✅ **训练张量首选**（h5py 风格 API） |
| VTK/VTU/VTP | 可视化生态 | 🟡 保留为中间态（与 NeMo 工具链兼容） |

**关键工程事实（✅ 已核实）**：
- **HDF5 并行 I/O 的陷阱**：所有 rank 独立读元数据会造成竞争。HDF Group 实测：**1024 rank 时原版元数据读耗时 150 s → 改用 collective metadata API 后 0.4 s（375×）** — [SC19 CGNS 演讲](https://www.hdfgroup.org/wp-content/uploads/2019/11/SC19_CGNS.pdf)
- ⭐ **Zarr 的生产级先例**：**Model-Parallel FNO** 把训练集放在 Azure Blob **Zarr** 格式，每个 MPI rank 直接从对象存储读自己负责的域，**任何时刻不需要单卡装下全量**；在 Sleipner CCS 基准上比 OPM 求解器快 **1386×** — [arXiv:2204.01205](https://arxiv.org/abs/2204.01205)
  → **这是"训练数据不出厂 + 大规模训练"的直接技术模板**

### 4.2 ⭐ "四元组"对应机制（数据血统）

```
case_id/
├── geometry/           STEP/Parasolid 原件 + geometry.sha256
├── mesh/               CGNS + mesh.sha256 + generator_version + mesh_seed
├── deck/               输入卡 + deck.sha256 + 材料库版本 + 求解器 commit
├── results/            CGNS/HDF5 + results.sha256 + 收敛历史 + 守恒残差
├── manifest.json       ← 唯一真相来源
├── solver/             求解器二进制哈希 / 容器 digest + git commit + 依赖锁
└── provenance.json     ← 血缘（谁、何时、用什么算的、运行时长）
```

| 要素 | 规范 | 关键字段 |
|---|---|---|
| Geometry 哈希 | SHA-256 over 规范化 STEP 字节流 | 几何版本、坐标系、单位、公差 |
| Mesh 哈希 | SHA-256 over CGNS | 生成器版本、种子、边界层数、**网格质量统计（最小雅可比、skewness）** |
| 输入卡哈希 | SHA-256 over deck + **材料库版本 + 求解器 commit** | k/E/ν/μ + 来源批次 + BC 定义 |
| 结果哈希 | SHA-256 over CGNS | 收敛历史、守恒残差、迭代数、墙钟时间 |
| manifest.json | 单一真相；**四元组绑定点** | sample_id → {geometry_sha, mesh_sha, deck_sha, results_sha, model_version, train_manifest_sha} |

**选型与工程量**：

| 项 | 推荐 | 量级 |
|---|---|---|
| 大文件版本化 | **DVC** 或 **lakeFS** | 2–4 人周 |
| 小文件与元数据 | Git | — |
| 实验追踪 | **MLflow** 或 **W&B** | 1–2 人周 |
| 权重与模型注册 | MLflow Model Registry 或自建（manifest 绑定）| 1–2 人周（**权重必须绑定训练 manifest 哈希**） |
| Schema 治理 | JSON Schema / Pydantic 强校验 | 2–3 人周 |
| **合计** | | **≈ 3–6 人月**（**必须在第一个客户交付前完成**） |

⭐ **红线**：**没有 manifest.json 的算例，一律不得进入训练集。** 写进 CI。

### 4.3 仿真 CI/CD

```
PR 触发
 ├─[1] 静态检查 ~2min │ [2] 编译(CPU/CUDA/昇腾) ~10min │ [3] 单元测试(离散算子守恒) ~5min
 ├─[4] 快速回归(FAST: ~10 算例，含 4 个 MMS) ~20min
 ├─[5] 门禁判定 → 通过/阻断
夜间
 ├─[6] 全量回归(FULL: ~100 算例，含 NAFEMS 全集) 4-8h │ [7] 漂移分析 ~30min │ [8] 超阈值→告警+开 issue
每月
 └─[9] 重基线（重生成基线网格与参考解；重算 GCI）1-2 天
```

**容差判定（必须与网格/收敛阶绑定，禁止固定百分比）**：

| 判据 | 阈值 | 依据 |
|---|---|---|
| 质量/能量/动量守恒残差（每步迭代） | 相对漂移 ≤ **1e-4** | 耦合求解器最易出守恒 bug |
| MMS 收敛阶 vs 理论阶 | ≥ 理论阶 **− 0.5** | ASME V&V 20 |
| 2 阶格式 MMS 绝对误差 | ≤ **1e-3**（无量纲化） | 同上 |
| GCI（3 层网格，Fs=1.25） | GCI_21 ≤ **1.05** | ASME V&V 20 |
| NAFEMS 基准相对参考解 | ≤ **2%** | 工业惯例 |
| 与自研求解器 baseline 的差 | ≤ **1%**（场量 L2 相对） | 回归基线 |
| **代理模型误差** | 峰值量 ≤ **10%**，P95 ≤ 20% | 对应 §2.3 |

**⭐ GPU 非确定性的诚实处理**：OpenFOAM v2606 官方明示 GPU 并行会改变 loop 结构（cell-based vs face-based），**影响截断误差，结果与 CPU 运行略有不同** — [官方发布说明](https://www.openfoam.com/node/684)。
→ **建议**：同一算例固定 commit 哈希 + 固定硬件；**跨硬件的结果差异单独标注，不混入回归基线**；单算例连续 3 次非确定性漂移必须人工复核。

**算力预算**：PR 快速回归 ≈50 GPU·h/日；夜间全量 ≈300–800 核·h/日；每月重基线 ≈3,000–6,000 核·h/月。
→ **起步 1 台 8 卡 4090 服务器 + 1 台大内存 CPU 节点；半年内扩到 2 台 8 卡。**

### 4.4 算力与调度

| 规模 | 建议 |
|---|---|
| 1–2 节点 / 4–16 GPU / 2–6 人且互相知道 | **不需要调度器**。SSH + tmux + `nvidia-smi` + 一份 GPU 占用约定 markdown |
| 4–32 节点批处理训练 | **Slurm** |
| 推理服务对外 | Kubernetes + GPU Operator（+ Kueue/Volcano） |
| 混合 | K8s 底座 + Kueue + Volcano；或 Slurm 管训练、K8s 管服务 |

⭐ **对 FEMAI 的结论（今天就执行）**：
> **20 人、预计 ≤32 张 GPU → 不要上 Slurm/K8s。** 引入调度器的运维成本会超过收益。
> ① `tmux` + `nvidia-smi` + **一份明确的 GPU 占用约定 markdown**
> ② 队列感知用 **Ray**（在 SLURM/K8s 之上做分配，**不作为顶层调度器**）
> ③ **设一条明确升级线**：GPU 数 > 16 **或** 使用者 > 8 且出现"抢卡" → 引入 Slurm

**资源隔离**：NVIDIA **MIG**（Blackwell 支持；单 A100 可切 7 实例，推理密度 3×）；训练/推理默认 60/40 分配、每 15 min 动态再平衡；**IGX Thor 官方支持 MIG 的"robust workload isolation"** —— 这是工作盒多模型共存的正解。

**国产算力适配成本（🟡 绝大多数为中文二手来源，不可作为对客户承诺）**：

| 构成 | 公开说法 | 置信度 | 评估 |
|---|---|---|---|
| 标准算子迁移 | torch_npu 一键迁移；CANN 适配 **约 2–5 人天** | 🟡 二手 | 🟢 推理端基本可接受 |
| 通用 CUDA 算子自动转换 | **90% 通用 CUDA 算子无人工改造**，迁移工时压缩至 **31%** | 🟡 二手 | 🟢 对纯 PyTorch 推理模型是强利好 |
| 强 CUDA 依赖模型 | 标准模型 **1–3 天**；**强 CUDA 依赖可能需 1–2 周**重写算子与通信层 | 🟡 二手 | ⚠️ **对训练端是真实风险**：自定义 GNO kernel、GPU hash-table 邻域搜索、集合通信 |

⭐ **结构性建议（最重要的一条）**：
> **把 CUDA 专有算子隔离在薄层，把 ONNX 作为跨平台中间表示。**
> ① 训练用 PyTorch + CUDA；② 部署前导出 **ONNX（opset 固定）**；③ NVIDIA 端 TensorRT，昇腾端 ONNX Runtime for Ascend / MindIE；
> ④ **所有自定义 CUDA kernel 必须有等价的 ONNX 可导出路径或 fallback 实现**。
> **这条约束今天就要写进代码规范——事后改造的成本是事前的 5–10 倍。**

### 4.5 ⭐ 代码质量与可追溯："一次交付，永久可复现"

**必须随交付物一同存在的 8 项**：

| # | 项目 | 说明 |
|---|---|---|
| 1 | 输入卡原文 + SHA-256 | 可被第三方求解器直接读取 |
| 2 | 几何源 + SHA-256 | 规范化字节流（消除时间戳噪声） |
| 3 | 网格 + SHA-256 + 生成器版本 + 种子 | 含网格质量统计 |
| 4 | **求解器身份** | 容器 digest + git commit + 依赖锁 —— **最容易被忽略、但最影响可复现** |
| 5 | 模型权重 + 训练 manifest 哈希 | 回答"这个权重对应哪批数据" |
| 6 | 环境镜像 digest | 基础镜像 digest，**不用 `latest` tag** |
| 7 | 随机性与收敛历史 | seed + 残差曲线 + 迭代数（GPU 非确定性的证据） |
| 8 | **`reproduce.sh` + 逐项对比报告** | 输入 = 交付目录；输出 = 重跑结果与原结果的逐项 diff（**容差必须显式声明**） |

**工程量**：交付目录规范 + schema 1.5–2 人月｜容器化 1–1.5 人月｜`reproduce.sh` + 对比工具 1–1.5 人月 → **合计 ≈3–6 人月**，之后每单维护 1–2 人日。**每季度审计 1 单**，验证 `reproduce.sh` 真的能跑通。

⭐ **为什么这是护城河而不是负担**：
> 客户真正买的是"**三个月后还能复现这个结论，并说服评审**"。
> CAE 结论进入设计决策后，**可复现性 = 可审计性 = 可追责性**。
> PhysicsX 官网强调 "maintaining full end-to-end data lineage" ✅ → **行业头部也在做这件事，说明这是被认可的必要能力**。
> ⭐ **在技术尽调中，能当场跑通 `reproduce.sh` 的演示，说服力超过 20 页架构图。**

## 六、⭐⭐⭐ 技术路线的三道"生死判断"

### 判断一：自研 CHT 求解器是否是正确选择？

**事实对照**：

| 维度 | 事实 | 状态 |
|---|---|---|
| 商业软件 | Ansys Fluent 2025R2：FGM + 预混燃烧**已 GPU 兼容 CHT**，川崎重工案例 **GPU vs CPU 8–10×**；面-面辐射 GPU 2–2.5× | ✅ [Ansys 官方](https://www.ansys.com/blog/whats-new-ansys-fluids-2025-r2) |
| 开源 CFD | OpenFOAM **v2606 首次 GPU offload**；**要求 GAMG + twoStageGaussSeidel**，禁用 DIC/DILU/GaussSeidel；**无 patch fusing → "far from the theoretical maximum"**；GPU 并行引入非确定性 | ✅ [官方](https://www.openfoam.com/node/684) |
| 开源 GPU 实测 | gpuFOAM：Cavity 8M cells **最佳 4.7×**（1 GH200 vs 1 核 ARM CPU）、**122.7×**（GH200+AMGx vs 1 核）；motorbike Large **32.5×** | ✅ [gpuFOAM.pdf](https://wiki.openfoam.com/images/4/45/GpuFOAM.pdf) |
| 开源 LBM | FluidX3D：**100–200×** vs 有限体积，**单一开发者**；waLBerla **1024×A100 / 32,768 CPU 核**，GPU 峰值 **86%**，4.3B cell 反转开式转子 | ✅ [arXiv:2502.20049](https://arxiv.org/abs/2502.20049) |
| 自研工程量 | L1 商用下限：20k–50k 行 + 50–200 回归 + 3–5 人 × 18–36 人月 | 🟡 推算 |

⭐ **结论**：
> **"自研 CHT 求解器"在性能维度上不是正确选择，在"数据主权"维度上也不是。它唯一可能正确的位置是第三个维度：数据引擎。**

| 候选动机 | 判定 | 论证 |
|---|---|---|
| ❌ **性能** | **不成立** | 商业 GPU-CHT 已 8–10×；开源 LBM 已 100–200× 且单开发者可实现；OpenFOAM 自己都在做 GPU offload 且承认"远未达理论上限"。**BP 的"5–10 倍"在 2026 年既不领先也不独特。继续以性能为由自研，是一场必输的军备竞赛** |
| ❌ **数据主权 / 离线** | **不成立** | 数据主权由**部署形态**决定，与求解器是否自研无关。自研求解器**不解决**数据主权，反而因维护更多代码**增加**供应链风险 |
| ❌ **成本** | **不成立** | 自研 L1 = 3–5 人 × 1.5–3 年。Code_Aster 免费且每日数千测试；OpenFOAM 免费且有 GPU 路线。**用 3–5 个工程师买回免费的东西，是最贵的采购** |
| ✅ **数据引擎（唯一正解）** | **成立** | 通用求解器**不输出**代理训练真正需要的量：伴随梯度 ∂J/∂x、接触反力**历史**、界面热流分量、几何梯度 ∂field/∂mesh、多体装配接触状态序列。**自研求解器若专门为这些量设计，就是不可替代的数据资产 —— 且这个理由与性能无关，不会被 Fluent 的 GPU 升级推翻** |
| 🟡 **控制权 / 供应链** | 部分成立 | 国产客户与国家队场景对"不受 Ansys 授权与出口管制约束"有真实需求；可用 Code_Aster（内部）+ 自研求解器（分发）的组合满足 |

**三条立即可执行的动作**：

| # | 动作 | 周期 | 收益 |
|---|---|---|---|
| 1 | **把自研求解器重新定位**为"代理模型数据引擎 + 可微分接口"；对外不再以"CHT 加速 5–10×"为技术卖点，改以"代理模型 + 几何语义"为技术卖点 | 立即 | **消除最易被证伪的叙事** |
| 2 | **引入一个成熟求解器作为 ground truth 生成器**（Code_Aster 首选：免费、每日数千测试、100 万行、35 年工业验证），**仅内部使用，不随产品分发** | 2–4 周 | 立即获得 NAFEMS 级精度基线，且**规避 GPL 传染性** |
| 3 | **给自研求解器定死 12 个月里程碑，缺一即止损**：① MMS 收敛阶 ≥ 理论阶−0.5（4 模块）；② NAFEMS 全集通过率 100%、单算例 ≤2%；③ 与 Code_Aster 同算例对照表；④ **输出伴随量与接触反力历史**（这才是它不可替代的证明） | 12 个月 | 避免"无止境的半成品" |

### 判断二："神经算子预条件器"是可持续资产，还是一次性突破？

| 维度 | 判定 | 论证 |
|---|---|---|
| **可复现性** | ❌ **低** | 该方向 2024–2026 每年多篇新方法；[2605.19867](https://arxiv.org/abs/2605.19867) 已表明**架构选择的微小差异就会导致 PCG 崩溃或停滞**。作为 20 人公司无法在方法论迭代上跟 Karniadakis 组竞争。**把"我用了神经算子预条件器"作为护城河，等于把护城河建在别人正在加固的公共地上** |
| **差异化** | ❌ **低** | [2605.07828 NSPOD](https://arxiv.org/abs/2605.07828) 已把"DeepONet 预条件子 + CAD 几何 + 固体力学"做完，且声称超过 AMG。**沿同一路线，2026 年内必然落后** |
| **作为内部手段** | ✅ **高** | 是**唯一能让代理模型结果"可迭代纠正"的技术**（S3 方案），与我方自研求解器天然耦合 |
| **作为研究/产品方向（转向后）** | ✅ **高** | ⭐ **接触是已核实的 0 篇空白**，工业需求明确（装配体、跌落、压装）。[2507.13459](https://arxiv.org/abs/2507.13459) 已证明可行（1000×）并指出"no studies to date" → **"首个覆盖接触的神经代理"仍是一个可争取的头衔** |
| **但必须承认的代价** | ⚠️ | 训练时间 2→18 天（9×）；摩擦历史依赖使**纯前馈代理原理上不可解**，必须走向状态化/递归代理 → 复杂度再上一个台阶 |

**四条落地建议**：

| # | 动作 | 周期 |
|---|---|---|
| 1 | 对外表述从"神经算子预条件器"改为"**面向接触与装配的物理场代理引擎**"；预条件器降为内部实现细节 | 立即 |
| 2 | **把预条件器做成"可替换组件"**：接口定义为 `solve(residual, geometry) → correction`，允许随时切换到 AMG/ILU。**不做可替换 = 把公司命运绑在一条 3 年就会过时的研究路线上** | 3 个月 |
| 3 | 把"接触"做成主攻（§2.3 实验设计），按预注册 H1–H4 执行。**12 个月内拿到"第一个可信证据"，哪怕结论是否证** | 5–7 个月 |
| 4 | 内部技术雷达：每月扫描 arXiv `cs.NA` + `physics.comp-ph` 的预条件子/算子学习新文，评估"是否需要替换我方组件" | 立即 |

### 判断三：三层耦合度多高？哪一层收入最快但护城河最浅？

| 层 | 收入速度 | 护城河深度 | 论证 |
|---|---|---|---|
| **L3 工作盒** | ⭐ **最快**（硬件 + 部署 + 采购偏好，交付周期最短，可复用现有硬件） | ❌ **最浅** | ① 技术栈完全标准（Triton/TensorRT/Jetson/昇腾）；② "100% 数据主权"是**采购偏好**，客户可自购 GPU + 装开源模型 + 部署 Triton 达到同样效果；③ 竞争者众多；④ **不积累数据、不积累模型、不积累信任**。**L3 是渠道与交付形态，不是技术产品** |
| **L2 智能体** | 🟡 中 | ⚠️ 浅（因 2026 SOTA 已公开且能力声明已对齐） | BenchCAD 已把"参数化 CAD 生成"标准化；RealCADBench 显示**真实工业意图下的泛化仍未解决** —— **机会在"工业落地"，陷阱在"通用能力无可差异化"**。可防守的窄切口是**装配体 + 面向制造意图**（Embodied CAD 路线） |
| **L1 引擎** | 🟡 中（需验证可信度，销售周期长） | ⚠️ 当前浅、但可加深 | 方法论层公开且拥挤；但**接触/装配这个具体交叉点是 0 篇空白**。**不是"L1 整体是护城河"，而是"L1 的接触/装配子域 + 与 L2 的语义耦合"是护城河** |
| **⭐ 真正的护城河（尚未建立）** | — | — | **"几何语义 → 物理场"的联合训练与联合验证闭环**：[2606.06405](https://arxiv.org/abs/2606.06405) 明确指出，现有几何表示"丢弃参数化与特征级语义，限制了与 CAD 驱动设计工作流的集成并降低模型可解释性"。**这正是三层唯一能形成正反馈的位置**：L2 的特征图 = L1 的几何编码输入；L1 的物理场预测 = L2 的设计决策依据；L3 收集的现场反馈 = 训练数据。**这条闭环一旦跑通，会随数据积累自我强化** |

**三层耦合度评级**：

| 耦合对 | 当前耦合度 | 证据 | 应有的耦合度 |
|---|---|---|---|
| L1 ↔ L2 | ❌ **几乎为零** | 官方配图显示 L2（设计工作台）与 L1（代理模型 GPINN v2.1）**并列展示，但未体现 L1 输出进入 L2 决策**或 **L2 特征进入 L1 训练** | ✅ **强耦合**：特征图作为 L1 几何编码；L1 的应力/温度场作为 L2 约束判据 |
| L1 ↔ L3 | 🟡 弱（部署关系） | 工作盒承载 L1 模型推理 | ✅ 保持弱耦合（保持可替换性） |
| L2 ↔ L3 | 🟡 弱 | 工作盒跑 CAD agent | ✅ 保持弱耦合 |

**五条决策建议**：

| # | 建议 | 理由 |
|---|---|---|
| 1 | **L3 工作盒：轻资产、快迭代、可替换**。不投 3 人以上，不自研硬件，不追求自研推理栈。**把它当渠道与交付形态，而非技术产品** | 它卖的是采购偏好；护城河浅。**过度投入 = 把 3 个最好的人放在最浅的护城河上** |
| 2 | **L2 智能体：收窄切口**。放弃"通用 CAD 智能体"（2026 已无差异化），聚焦 **"面向装配体 + 面向制造意图 + 与物理仿真联动"** | BenchCAD 已证明通用能力饱和；RealCADBench 已证明真实工业意图是未解难题。**窄切口才能赢** |
| 3 | **把 8–10 人压在 L1 × L2 的耦合点上**：① 定义中间表示（特征图/IR）；② 该表示同时是 L2 产物与 L1 输入；③ 建立联合训练与联合验证流水线 | ⭐ 唯一能形成数据飞轮的位置 |
| 4 | **把 L1 的对外技术品牌从"神经算子预条件器"迁移到"接触与装配的物理场代理 + 几何语义联合表征"** | 前者是红海，后者是空白 |
| 5 | **明确"L3 不做技术"这条纪律，写进技术战略文件** | **收入最快 ≠ 护城河最深。20 人公司最常见的死法，是把最好的人放在最容易收钱的地方** |
