# 改写后的原始问题

> **v2.0（2026-10-26）**：针对"**物理 AI × CAD/CAE 落地**"这一**交叉领域**重写。
> v1 改写版只覆盖了物理 AI / CAE 侧，**完全遗漏 CAD 与几何侧**——
> 而几何是落地的真正入口，不是配角。
>
> 改写的核心原则不变：
> **原问题要求"答 4 个问题"，但没要求回答者去做那些让答案可信的工作。**
> 改写后的版本把"可信度"写进了问题本身。

---

## 📌 原始问题（2026-10-26 首次提出）

> 阅读所有文档，重构我的文档，这是我自己的 Obsidian 现在用 github 管理，
> 内容现在不适合最近的工作和记录了，重构结构和所有内容，
> 针对指定领域，我是清航飞迈的产品负责人和 FDE，请依次完成下面 4 项任务：
>
> 1. 阐述该领域顶尖专家在处理同类问题时，会额外开展哪些我本次没有提出要求的工作；
> 2. 列出专家开展工作时会使用的原始一手素材（区别于已经加工、整理完成的材料）；
> 3. 列举专家会用到的具体研究方法、分析手段与专业工具；
> 4. 给出独立于你、我之外，能够核验、证明最终结论正确性的依据与验证渠道；
>
> 最后，请改写优化我的原始问题，让改写后的问题能够完整覆盖上面全部 4 项要求。

## 🔍 原问题漏掉了什么（v1 诊断 + v2 补充）

| # | 缺口 | 后果 |
|---|---|---|
| 1 | **没定义"指定领域"的范围** | 专家是谁、用什么标准、覆盖哪些子领域，全靠回答者猜 |
| 2 | **没要求"先定义问题，再回答"** | 直接跳过问题契约阶段，进入答题 |
| 3 | **没要求回答者先核查前提** | ⭐ 实测后果：4 个论文编号有 3 个指向无关论文；1 个标准号写错（JT 是 ISO 14306 非 14343）；2 个产品开源/商业分类错误；1 个 API 版本根本不存在 |
| 4 | **没要求区分事实与推断** | 二手转述与一手来源混在一起，无法追溯 |
| 5 | **没要求给出失败/证伪路径** | 只有"怎么证明对"，没有"怎么推翻" |
| 6 | **没要求成果可落地为流程** | 答案停留在阅读材料，没有变成可重复的作业标准 |
| 7 | **没要求标注核实状态** | 读者无法区分"已验证"与"凭记忆" |
| **8** | ⭐ **v2 新增：没点明 CAD/几何侧** | 物理 AI × CAD/CAE 是**两个学科的交叉**，只答 CAE 侧会漏掉真正的落地瓶颈 |
| **9** | ⭐ **v2 新增：没区分"可执行"与"正确"** | CAD 领域最隐蔽的失效：代码能跑、语法合法、几何完全错误（IR 2% 但 IoU ≈ 0） |
| **10** | ⭐ **v2 新增：没要求检查许可证** | TetGen 是 AGPLv3、Gmsh 商业静态链接需许可 —— 商业落地的法律地雷 |

## ✅ 改写后的问题

### 版本 A：完整版（推荐用于首次调研或进入新领域）

> **背景与角色**
>
> 我是清航飞迈（上海）科技软件有限公司的**产品负责人 + FDE（前置交付工程师）**。
> 公司产品矩阵：AICube（物理世界引擎 / 全栈自研 CAE 仿真层）、Solid（物理 AI 开发平台，
> 融合物理模型与神经算子）、LoopAxis（面向工程用户的即用型行业应用平台）。
> 标杆场景：C919 大型复材机翼仿真、先进装备（机器狗、电机优化）、
> 智慧医疗（3D 骨缺损修复、骨科术前规划）。
>
> **领域范围（本问题聚焦的交叉领域）**
>
> 请以「**物理 AI × CAD/CAE 落地**」为指定领域。这是一条**从几何到物理再到交付**的完整链路，
> 请覆盖以下四段，不要只答其中一段：
>
> - **几何与 CAD 段**：几何清理与 healing、几何简化与精度量化、几何深度学习、
>   CAD→CAE 数据传递与意图丢失、几何内核作为验证判官
> - **建模与求解段**：网格生成与网格质量、载荷工况建模、材料本构与失效判据、
>   边界条件策略、收敛判据
> - **物理 AI 段**：代理模型与神经算子的工程化落地、Sim2Real 差距、多保真融合、
>   求解器 AI 化（加速/降阶/自适应）
> - **交付与商业段**：仿真可信度评估（V&V）、PoC 与验收、客户现场交付、
>   行业合规（航空/医疗/汽车）、产品化沉淀与竞争定位
>
> **任务一：先定义问题，再回答**
>
> 1.1 在给出任何结论前，先建立**问题契约**：明确目标量、方向、约束、验收判据，
>     并说明你会主动向我追问哪些问题、以及哪些问题的答案会改变你的结论。
> 1.2 说明你使用的"**顶尖专家**"的判定标准（职责范围、代表机构/人物、可核验的产出物）。
> 1.3 列出你需要但**未获得**的信息，以及这些缺失会如何影响结论的可靠性。
>
> **任务二：专家会额外开展哪些我本次没有要求的工作**
>
> 针对上述交叉领域，专家在处理同类问题（交付一个客户仿真项目 / 定义一个仿真产品）
> 时，会额外开展哪些**我本次没有要求**的工作？
> 请**按链路环节**组织（几何 → 建模 → 求解 → 验证 → 交付 → 复盘 → 产品化），
> 并为每项说明**依据来源**（标准条款 / 公开一手材料 / 行业实践 / 已证实的失败案例）。
>
> **任务三：专家会使用的原始一手素材**
>
> 列出专家会使用的**原始一手素材**（区别于已经加工整理完成的材料），
> 每条必须给出：**来源机构或作者 + 可访问的具体链接 + 这份素材管什么 + 如何使用**。
> 请覆盖：
> - 原始学术文献（⚠️ 每个 arXiv 编号必须打开 abs 页核对标题与作者）
> - **CAD/几何侧**：CAD 内核与格式规范原文（含**标准现行/已撤销状态**）、
>   几何与网格处理开源库（**含许可证与维护状态**）、几何学习数据集与公开基准
> - CAE 侧：标准与行业规范、公开基准算例与数据集、求解器官方文档
> - 行业一手材料（官方期刊、协会、标准组织）
> - 采购与招投标公告原文、官方 release notes、专利检索入口、招聘 JD
>
> **任务四：专家会用到的研究方法、分析手段与专业工具**
>
> 分为**研究方法**（数值方法、降阶、UQ、敏感性分析、几何拓扑、验证确认、产品侧方法）、
> **分析手段**（每个环节的具体动作与判据）、**专业工具**（CAE 商业软件 / 开源求解器 /
> **CAD 与几何工具** / 神经算子库 / 交付协作工具）三类，
> 每项说明**用在哪个环节**，并对开源工具标注**许可证的商用风险**。
>
> **任务五：独立于你和我之外的核验依据与验证渠道**
>
> 给出三层核验路径：**存在性**（是否真实存在）、**准确性**（属性与数字是否正确）、
> **有效性**（是否真的能支撑结论）。
> 请提供可点击的具体链接，并额外给出：
> - ⭐ **反向验证 / 证伪方法**——如何主动推翻一个看似合理的结论（至少 5 条）
> - ⭐ **本领域特有的验证优势**——例如 CAD/CAE 输出是有精确数学定义的实体，
>   因此几何内核可否作为"确定性判官"？如何用？
>
> **任务六：输出要求**
>
> 6.1 **核实状态标注**：每条事实必须标 ✅已核实（说明如何核实的）/ ⚠️二手待复核 / ❌已核实为错误。
> 6.2 **区分"可执行"与"正确"**：对任何生成类方案，明确说明验收标准是"能跑"还是"结果正确"，
>     并给出后者的判定手段。
> 6.3 **落地为流程**：把核验要求固化为一份可重复执行的**核验清单**（含许可证检查）。
> 6.4 **区分事实与推断**，推断必须写明推断依据。
> 6.5 明确列出**未能核实**的条目及原因。
>
> **任务七：最后，改写我的原始问题**
>
> 在保留我的真实意图的前提下，改写出**一个更好的问题**，
> 使其能够完整覆盖上述全部要求，并使回答者**不容易犯"未核实就断言"的错误**。

### 版本 B：精简版（用于日常快速调用）

> 我是清航飞迈的产品负责人 + FDE，领域是**物理 AI × CAD/CAE 落地**
> （链路：几何/CAD → 建模/网格 → 物理 AI 代理模型 → V&V 交付；
> 场景含 C919 复材机翼、先进装备、骨科植入物）。
>
> 请针对该交叉领域回答：
> 1. **专家额外会做哪些我没要求的工作**（按链路环节组织 + 依据来源）；
> 2. **专家会用哪些原始一手素材**（给出来源 + 链接 + 管什么 + 怎么用）；
> 3. **专家会用哪些研究方法、分析手段与专业工具**（说明用在哪个环节 + 许可证商用风险）；
> 4. **如何被独立于你我之外的人核验**（存在性/准确性/有效性三层 + 证伪方法）。
>
> **输出约束**：
> - 每条事实标 ✅已核实（说明核实方式）/ ⚠️二手待复核 / ❌已核实为错误；
> - 给可点击链接；
> - 明确列出未能核实项及原因；
> - 区分事实与推断；
> - **区分"可执行"与"正确"**，给出正确性判定手段；
> - 把核验要求固化为可复用的**核验清单**（含许可证检查）；
> - 最后改写出能完整覆盖以上要求的更好问题。

### 版本 D：⭐ 领域新人的 90 天学习调研版

> 我刚进入物理 AI × CAD/CAE 落地领域，担任产品负责人 + FDE。
> 请设计一份**可执行的调研方案**，而不是知识罗列：
>
> 1. **按链路环节**（几何 → 建模 → 求解 → 验证 → 交付），
>    每个环节我应该先掌握什么、最容易踩什么坑、到哪里取一手材料；
> 2. 给出**每阶段的可交付物**（如"跑通 NAFEMS 基准并出一份对标报告"）；
> 3. 列出我**必须亲自动手**的事（哪些只读文档是学不会的）；
> 4. 标注哪些内容**已有成熟标准**（照做即可）、
>    哪些是**正在形成中的标准**（早参与可获话语权，如 ASME VVUQ 70/90、CAx-IF 推荐实践）；
> 5. 所有结论按 ✅/⚠️/❌ 标注核实状态。

## ⭐ 为什么这样改写才有效

| 改写点 | 对应解决的具体问题 |
|---|---|
| **先定义问题，再回答** | 避免跳过问题契约阶段 |
| **明确交叉领域与四段链路** | ⭐ 避免只答 CAE 侧、漏掉几何侧这个真正的落地瓶颈 |
| **明确专家判定标准** | 避免范围漂移、避免"专家"定义随意 |
| **要求核实状态标注** | ⭐ 直接解决编号幻觉 / 标准号错误 / 分类错误 |
| **要求给核实方式与链接** | 让结论可被独立复现 |
| **⭐ 要求区分"可执行"与"正确"** | ⭐ 解决 CAD 领域最隐蔽的失效模式 |
| **⭐ 要求检查许可证商用风险** | 避免 TetGen/AGPL、Gmsh 静态链接等法律地雷 |
| **要求区分事实与推断** | 避免把推断当事实传播 |
| **要求列出未能核实项** | 诚实暴露边界，而不是伪装完整 |
| **加入证伪方法** | 从"证明对"升级为"能推翻" |
| **要求固化为核验清单** | 从一次性答案升级为可重复流程 |
| **最后改写问题** | 让方法论本身可传递 |

> ⭐ **最关键的两条是"核实状态标注"和"区分可执行与正确"。**
> 前者把开放题变成**可被审计的交付物**；
> 后者防止整个项目在"看起来一切正常"的地雷上翻车。
