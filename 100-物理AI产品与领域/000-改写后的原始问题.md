# 改写后的原始问题

> **原始问题**与**改写后的问题**对照。
> 改写的原则：原问题要求"答 4 个问题"，但**没要求回答者去做那些让答案可信的工作**。
> 改写后的版本把"可信度"写进了问题本身。

---

## 📌 原始问题（2026-10-26 提出）

> 阅读所有文档，重构我的文档，这是我自己的 Obsidian 现在用 github 管理，
> 内容现在不适合最近的工作和记录了，重构结构和所有内容，
> 针对指定领域，我是清航飞迈的产品负责人和 FDE，请依次完成下面 4 项任务：
>
> 1. 阐述该领域顶尖专家在处理同类问题时，会额外开展哪些我本次没有提出要求的工作；
> 2. 列出专家开展工作时会使用的原始一手素材（区别于已经加工、整理完成的材料）；
> 3. 列举专家会用到的具体研究方法、分析手段与专业工具；
> 4. 给出独立于你、我之外，能够核验、证明最终结论正确性的依据与验证渠道；
>
> 最后，请改写优化我的原始问题，让改写后的问题能够完整覆盖上面全部 4 项要求。

---

## 🔍 原问题漏掉了什么

| # | 缺口 | 后果 |
|---|---|---|
| 1 | **没定义"指定领域"的范围** | 专家是谁、用什么标准、覆盖哪些子领域，全靠回答者猜 |
| 2 | **没要求"先定义问题，再回答"** | 直接跳过问题契约阶段，进入答题 |
| 3 | **没要求回答者先核查前提** | ⭐ **实测后果**：库中 4 个论文编号有 3 个指向无关论文；产品名有 2 个虚构；一个 API 版本根本不存在 |
| 4 | **没要求区分事实与推断** | 二手转述与一手来源混在一起，无法追溯 |
| 5 | **没要求给出失败/证伪路径** | 只有"怎么证明对"，没有"怎么推翻" |
| 6 | **没要求成果可落地为流程** | 答案停留在阅读材料，没有变成可重复的作业标准 |
| 7 | **没要求标注核实状态** | 读者无法区分"已验证"与"凭记忆" |

## ✅ 改写后的问题

### 版本 A：完整版（推荐用于首次调研或进入新领域）

> **背景与角色**
>
> 我是清航飞迈（上海）科技软件有限公司的**产品负责人 + FDE（前置交付工程师）**。
> 公司产品矩阵为：AICube（物理世界引擎 / 全栈自研 CAE 仿真层）、Solid（物理 AI 开发平台，
> 融合物理模型与神经算子）、LoopAxis（面向工程用户的即用型行业应用平台）。
> 标杆场景：C919 大型复材机翼仿真、先进装备（机器狗、电机优化）、
> 智慧医疗（3D 骨缺损修复、骨科术前规划）。
>
> **领域范围**
>
> 请以「**物理 AI 工业软件（CAE 仿真 + 代理模型/神经算子 + 客户前置交付）**」为指定领域，
> 覆盖但不限于：数值仿真方法与求解器选型、仿真可信度评估（V&V）、
> 代理模型与神经算子的工程化落地、Sim2Real 差距、CAE 产品定义与商业化、客户交付与验收。
>
> **任务一：先定义问题，再回答**
>
> 1.1 在给出任何结论前，先建立**问题契约**：明确目标量、方向、约束、验收判据，
>     并说明你会主动向提问者追问哪些问题、以及哪些问题的答案会改变你的结论。
> 1.2 说明**你使用的"顶尖专家"的判定标准**（如职责范围、代表机构/人物、可核验的产出物）。
> 1.3 列出你需要但**未获得**的信息，以及这些缺失会如何影响结论的可靠性。
>
> **任务二：专家会额外开展哪些我本次没有要求的工作**
>
> 针对上述领域，专家在处理同类问题（交付一个客户仿真项目 / 定义一个仿真产品）时，
> 会额外开展哪些**我本次没有要求**的工作？
> 请覆盖前期问题定义、建模、求解、验证、交付、复盘、产品化沉淀各环节，
> 并说明每项的**依据来源**（标准条款 / 公开一手材料 / 行业实践）。
>
> **任务三：专家会使用的原始一手素材**
>
> 列出专家会使用的**原始一手素材**（区别于已经加工整理完成的材料），
> 每条必须给出：**来源机构或作者 + 可访问的具体链接 + 这份素材管什么 + 如何使用**。
> 请覆盖：原始学术文献、标准正文、公开基准算例与数据集、行业一手发布、
> 竞品官方文档与定价、采购与招投标公告、专利检索入口、招聘 JD、一手现场记录。
>
> **任务四：专家会用到的研究方法、分析手段与专业工具**
>
> 分为**研究方法**（数值方法、降阶、UQ、敏感性分析、验证确认方法、产品侧方法）、
> **分析手段**（每个环节的具体动作与判据）、**专业工具**（CAE 商业软件 / 开源求解器 /
> 神经算子库 / CAD 与几何 / Python 生态 / 交付协作工具）三类，
> 每项说明**用在哪个环节**。
>
> **任务五：独立于你和我之外的核验依据与验证渠道**
>
> 给出三层核验路径：**存在性**（是否真实存在）、**准确性**（属性与数字是否正确）、
> **有效性**（是否真的能支撑结论）。
> 请提供可点击的具体链接，并额外给出**反向验证 / 证伪方法**——
> 即如何主动推翻一个看似合理的结论。
>
> **任务六：输出要求**
>
> 6.1 **核实状态标注**：每条事实必须标 ✅已核实（说明如何核实的）/ ⚠️二手待复核 / ❌已核实为错误。
> 6.2 **落地为流程**：把核验要求固化为一份可重复执行的**核验清单**（可复用模板）。
> 6.3 **区分事实与推断**，推断必须写明推断依据。
> 6.4 明确列出**未能核实**的条目及原因。
>
> **任务七：最后，改写我的原始问题**
>
> 在保留我的真实意图的前提下，改写出**一个更好的问题**，
> 使其能够完整覆盖上述全部要求，并使回答者**不容易犯"未核实就断言"的错误**。

### 版本 B：精简版（用于日常快速调用）

> 我是清航飞迈的产品负责人 + FDE，领域是物理 AI 工业软件
> （CAE 仿真 + 神经算子代理模型 + 客户前置交付；场景含 C919 复材机翼、先进装备、骨科植入物）。
>
> 请针对该领域回答：
> 1. **专家额外会做哪些我没要求的工作**（含依据来源）；
> 2. **专家会用哪些原始一手素材**（给出来源 + 链接 + 管什么 + 怎么用）；
> 3. **专家会用哪些研究方法、分析手段与专业工具**（说明用在哪个环节）；
> 4. **如何被独立于你我之外的人核验**（存在性 / 准确性 / 有效性三层 + 证伪方法）。
>
> **输出约束**：
> - 每条事实标 ✅已核实（说明核实方式）/ ⚠️二手待复核 / ❌已核实为错误；
> - 给出可点击链接；
> - 明确列出未能核实项及原因；
> - 区分事实与推断；
> - 把核验要求固化为可复用的**核验清单**；
> - 最后改写出能完整覆盖以上要求的更好问题。

### 版本 C：单领域速查（用于具体技术决策）

> 我在物理 AI 工业软件领域做产品与交付。
> **现在要判断：____（具体技术/产品决策）**
>
> 请回答：
> 1. 该领域顶尖专家在处理这类决策时，会额外做哪些我没要求的工作？
> 2. 他们会查阅哪些原始一手素材（给链接）？
> 3. 会用哪些研究方法、分析手段与工具？
> 4. 结论如何被第三方独立核验？有哪些反向证伪手段？
>
> 所有事实标 ✅/⚠️/❌ 核实状态；给出可点击链接；列出未能核实项。
> **特别关注**：本领域的"编号幻觉""产品名幻觉""精度通胀"三类错误。

## ⭐ 为什么这样改写才有效

| 改写点 | 对应解决的具体问题 |
|---|---|
| **先定义问题，再回答** | 避免跳过问题契约阶段 |
| **明确领域范围与专家判定标准** | 避免范围漂移、避免"专家"定义随意 |
| **要求核实状态标注** | ⭐ 直接解决"编号幻觉""产品名幻觉" |
| **要求给核实方式与链接** | 让结论可被独立复现 |
| **要求区分事实与推断** | 避免把推断当事实传播 |
| **要求列出未能核实项** | 诚实暴露边界，而不是伪装完整 |
| **加入证伪方法** | 从"证明对"升级为"能推翻" |
| **要求固化为核验清单** | 从一次性答案升级为可重复流程 |
| **最后改写问题** | 让方法论本身可传递 |

> ⭐ **最关键的一条是"核实状态标注"。**
> 它把一个开放题变成了**可被审计的交付物**——
> 读者一眼就知道哪些能直接引用、哪些要先自己验一遍。
