# FDE 角色与工作标准

> **FDE 这个角色最容易被误用，也最容易产生真正的护城河。**
> 这份文档把角色定义、交付标准、评审机制写成可执行的规范。

---

## 一、FDE 的原始定义

**出处**：Palantir 官方博客《A Day in the Life of a Palantir Forward Deployed Software Engineer》
（内部代号 **FDSE**，代号 "Delta"）

### 核心对比（Palantir 原话）

> "You can think of a **Dev's focus as 'one capability, many customers,'
> while a Delta's focus is 'one customer, many capabilities.'**"

| | Dev | FDE / Delta |
|---|---|---|
| 焦点 | 一个能力服务多个客户 | 一个客户用上多个能力 |
| 做法 | 造平台 | 从现成平台里"取件组装"（compose ready-built pieces），不重造轮子 |
| 与顾问的区别 | —— | 顾问做拼装方案；Delta 用现成件组装 |

### 关键的一条：闭环回产品

> "While FDSEs typically configure software for a particular customer, we often find that our configuration solutions
> could prove beneficial for many other customers. **In fact, some of our most valuable product additions originated in the field
> through this process!**"

> ⭐ **这条直接定义了 FDE 的 KPI 必须包含"回流到产品的比例"。**
> 没有回流，FDE 团队会退化为纯项目外包，Solid 和 LoopAxis 平台就永远形不成。

## 二、⭐ FDE 岗位真伪的"四问"检验法

由 A.Team 提出（基于 1000 个 JD 的统计）：

| # | 问题 | 判断意义 |
|---|---|---|
| 1 | **谁的系统**？代码落在客户的仓库还是供应商的？ | 落客户仓库 = 定制外包；落供应商 = 产品化 |
| 2 | **什么坏了**？ | 描述的是技术问题还是需求问题 |
| 3 | **谁采纳了**？ | 有没有真实的决策者 |
| 4 | **财务衡量了什么**？ | 衡量的是软件许可还是人力工时 |
| 5 | **什么回到了产品**？ | ⭐ 最有判别力的一问 |

### 独立数据（2026 年）

| 指标 | 数值 |
|---|---|
| 24 个月内 FDE 岗位增长 | 约 **40 倍**（Insight Partners, 2026-07） |
| 982 个在招 FDE 岗位薪资中位数 | **$188K**（Plank census, 2026-09-04） |
| **1000 个 FDE JD 中带销售配额的比例** | **0%**（Bloomberry / Revealera） |
| AWS 承诺投入 | 约 $10 亿 |
| Microsoft Frontier | 约 $25 亿，约 6000 名嵌入式专家 |

> "FDE 只是换皮的销售工程师"这一质疑，约 **30% 成立**——**quota 数据是判别依据**。

## 三、⭐ 客户需求的工程化翻译

FDE 的第一件事**不是建模，是反向提问 + 建立问题契约**。

### 第一步：把模糊需求拆成四个可判定量

| 要素 | 问题 | 示例 |
|---|---|---|
| **目标量** | 要优化什么 | 质量 / 成本 / 寿命 |
| **方向** | 在什么约束下优化 | 减重但强度不降？降本但刚度不变？ |
| **约束** | 边界在哪 | 法规许用值、工艺能力、材料体系 |
| **验收判据** | "轻一点"到底是什么 | ≤X kg，还是 ≤X% 且 ≥Y 倍安全裕度 |

### 第二步：建立约束台账（Constraint Log）—— 最容易漏掉的一步

逐项记录：

- 载荷谱（含工况包络）
- 材料（含批次与方向性铺层）
- 几何制造约束（最小铺层厚度、纤维角、圆角半径、铺层搭接）
- 连接与边界（胶接/机械连接刚度）
- 温度湿度环境
- 适航或规范条款编号

### 第三步：定义参数空间

> ⭐ **专家会明确写出"优化空间 ≠ 允许空间"，并在 PoC 阶段就声明被排除的区域。**

- **可变参数**（层板角度、铺层数、厚度）→ 优化空间
- **不可变参数**（认证许用值下限、工艺限制）→ 约束边界

### 第四步：几何简化及其论证

去掉倒角、螺栓孔、粘接区细节，但**必须量化说明"该简化对目标量的影响 < X%"**。
这个证据来自网格无关性与 GCI，**不是来自直觉**。

### 第五步：DFMA 前置

中国商飞复材机翼项目公开材料明确采用"**面向制造装配的设计（DFMA）理念**"，
并通过典型盒段和全尺寸盒段试验件制造、装配进行验证。

> **专家做法相同：在优化开始前就把铺层可制造性作为硬约束写进问题定义**，
> 而不是等优化出结果再筛。

## 四、⭐ 反直觉的专业回答：把"不能"做成合法交付物

> **在航空/医疗场景里，一个基于不可信模型的减重承诺会直接导致适航或临床风险。**

顶尖产品负责人会给"这个结构能不能轻一点"一个**专业性的否定性回答**。
把不可行性**证成**（带 GCI 数字），比给一个乐观的减重数字**更有价值**。

## 五、⭐ PoC 设计原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | **必须用客户的真实几何、真实工况、真实材料** | —— |
| 2 | **PoC 阶段就必须暴露"简化假设"清单** | 客户最容易被"漂亮云图"收买；后期发现简化不可接受时**信任崩塌** |
| 3 | **在 PoC 报告里同时给出"简化清单"和"简化影响量级"** | —— |
| 4 | **验收门槛是"方法论门槛"而非"结果门槛"** | 见下方门槛建议 |
| 5 | **预先声明"不做什么"** | 不做疲劳寿命、不做损伤容限、不做环境影响、不覆盖某工况区间 |
| 6 | **成功标准写进合同附件** | 不是"以客户满意为准" |
| 7 | **设置退出机制** | 如："若 GCI 无法达到 5%，本方案退化为传统求解器交付" |

### 建议的 PoC 验收门槛

- [ ] 网格无关性研究完成，**GCI ≤ 5%**
- [ ] 与客户提供的历史试验/对标件对比，偏差在约定带内
- [ ] 关键输出量在 **NAFEMS 基准**上复现
- [ ] 报告格式符合 **GB/T 33582-2017** 的"结果评估 / 结果输出 / 报告编写"章节结构
- [ ] 单工况求解在 X 核时内收敛
- [ ] 目标输出量相对试验偏差 ≤ Y%
- [ ] 提供**可复现的求解输入卡与运行脚本**

> ⭐ **退出机制保护客户，也保护 FDE 的交付团队不被自己公司的技术预期绑架。**

## 六、评审会机制

### 四段式评审

| 阶段 | 内容 | 提交方 |
|---|---|---|
| **① 预审（Pre-review）** | 网格无关性、收敛历史、算例设置、**假设清单**、脚本可复现性检查 | 计算负责人 |
| **② 模型评审（Model Review）** | 几何、材料、载荷、边界、本构、耦合假设，**逐条**过 | 双方共同签字 |
| **③ 结果评审（Results Review）** | GCI、判据、对比图、**异常清单** | 双方 |
| **④ ⭐ 复盘（Post-project Review）** | "这个项目我们做错了什么、下次怎么避免" | 双方 |

> ⭐ **复盘必须是结构化的、写入产品需求文档的，而不是口头。**

### 失败复盘的议题模板

- 哪个工况算不出来？为什么（不收敛 / 超出训练域 / 超内存 / 材料模型缺失）？
- 代理模型在哪个参数区间失效？**失效阈值是多少**？
- 哪个假设被客户推翻了？成本是多少？
- **哪个可复用资产没有沉淀？卡在哪个环节？**

## 七、⭐ 交付验收与报告规范

### 结果血缘（Provenance）包 —— 随结果一起交付

```
□ 求解器版本与编译选项
□ 网格文件
□ 输入卡
□ 材料卡
□ 边界条件
□ 求解日志
□ GCI 研究（网格无关性报告）
□ 迭代收敛历史
□ 随机种子 / 模型权重 hash
□ 后处理脚本
```

> ⭐ NAFEMS 互操作报告的核心论断：
> "缺乏元数据的仿真结果仍被锁死，**缺乏支撑高后果决策所需的血统**。"
> **没有元数据的结论无法支撑高后果决策。**

### 责任边界与签署链

| 层级 | 签署人 | 承担什么 |
|---|---|---|
| 1 | CAE 分析师 | 计算、建模的正确性 |
| 2 | 方法负责人 | 模型的适用性 |
| 3 | 项目责任人 | **用途适配**（唯一承担用途责任的一层） |

**并明确定位"证据等级"**：
本结果适用于 **方案比选** / 适用于 **设计放行** / 适用于 **适航符合性证据** ——
三者法律与工程含义**完全不同**。

## 八、协作模型

| 场景 | 仿真专家（FEMAI 侧） | 客户工程师侧 |
|---|---|---|
| 问题定义 | 提供问题契约模板、约束清单、可行性预判 | 掌握真实工况、试验数据、决策约束 |
| 建模 | 网格/材料/边界设置、收敛与 GCI | 审核几何与载荷合理性、DFMA 可制造性 |
| 求解 | 求解器参数、不收敛排查、算力调优 | —— |
| 后处理 | 提取目标量、生成对比图 | 判断结果是否符合工程直觉、找异常 |
| 验证 | 对标基准、与试验数据对比 | 提供试验数据与验收判据 |
| 交付 | 报告（GB/T 33582 结构）、可复现输入卡 | 评审、签署、归档 |

> ⭐ **专家的额外动作：把"客户工程师的直觉"当作验证工具而非干扰。**
> 资深仿真专家的直觉通常能提前发现建模错误——
> 但**必须把直觉翻译成可检验的数值指标**（网格、奇异点、收敛历史）才能留痕。

## 九、⭐ 从客户需求到产品化的四层沉淀

| 层级 | 沉淀物 | 归属 | 举例 |
|---|---|---|---|
| **L1 模板** | 行业问题的建模模板（几何+材料+工况+后处理） | LoopAxis | 骨植入物几何模板、复材盒段建模模板 |
| **L2 参数库** | 材料本构库 / 载荷谱库 / 许用值库 / 单元库 | AICube / LoopAxis | T800 级复材层合板性能库、载荷谱库 |
| **L3 求解器插件化** | 材料模型 / 单元 / 单元算法 / 求解后处理作为可插拔接口 | AICube | 自研高保真断裂程序 |
| **L4 API/SDK** | 供客户二次开发的编程接口 + 示例 + 版本策略 | Solid | 对标 Ansys PyAnsys |

### API 设计对标：Ansys PyAnsys

- **按物理域分库**：PyMAPDL（结构）/ PyFluent（流体）/ PyMechanical / PyDPF（后处理）/ PyDYNA / PyOptiSLang（优化）/ PyACP（复材 PrepPost）/ PyDPF-Composites / PySystemCoupling（多物理场耦合）/ PyTwin（数字孪生）
- **每库"Core + 高层封装"双层 API**（PyDPF-Core / PyDPF-Post / PyDPF-Visualization / PyDPF-Composites）
  → **Core 层给全功能，Post 层给易用**
- ⭐ **嵌入模式 vs 远程会话模式双轨**
  - 嵌入模式：in-process，快、无网络通信、适合 Jupyter
  - 远程会话模式：进程隔离、支持 GUI、**适合 CI/CD 部署**

> ⭐ **对 LoopAxis 尤其重要**：其界面在浏览器中运行、输出 `prediction_result.json`。
> **若要进入军工航空客户的 CI/CD，必须同时提供远程/批处理模式。**

## 十、⭐ 我的 FDE KPI 草案

| 维度 | 指标 | 目标 |
|---|---|---|
| **交付结果** | PoC 转正率 | —— |
| | 交付物一次性验收通过率 | —— |
| **⭐ 回流** | 本次交付沉淀进 L1–L4 的资产数 | —— |
| | 回流资产被其他客户复用的次数 | —— |
| **能力** | 团队 NAFEMS PSE 持证数 | —— |
| | 参与 ASME VVUQ / VMAP SC 的贡献 | —— |
| **可信度** | 对标基准跑通并公开的结果数 | —— |

> ⭐ **"回流"两项是 FDE 与外包的分水岭。**
> 没有这两项，C919、美的电机、两家三甲医院就只是三个项目；
> 有了这两项，才有竞品买不到的行业知识资产。
