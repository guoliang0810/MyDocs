# 竞品作战手册

> **《竞品地图》回答"谁是谁"；本手册回答"怎么打"。**
> 差别很大：地图是静态的档案，作战手册是**可执行的、可更新的、被验证过的**。
>
> ⭐ **本手册最反直觉的一条**：
> **我们最该读的从来不是竞品的官网，是客户的招标文件和竞品的中标公示。**

---

# 一、⭐⭐ Battlecard：11 个必填格

> **Battlecard 不是"竞品功能表"，是"输赢的原因"。**
> 它的输出应该是"我们赢在哪、输在哪、下次该怎么打"，而不是"他们有什么功能"。

## 1.1 十一个格子

| # | 格 | 填什么 | ⭐ CAE 领域的具体填充要求 |
|---|---|---|---|
| **1** | **Header** | 竞品名 + 最常遇到的产品线；**Card owner**；**最后复核日期 / 下次复核日期**；**来源清单**（win/loss 记录、招标公示、对方官网、日期）；**内部专用，不得转发客户** | 来源必须**逐条标日期**。CAE 竞品版本迭代快（2026-07-23 才发布 3DEXPERIENCE AI 商业版），⭐ **超过 6 个月未复核的 card 直接作废** |
| **2** | **Snapshot：他们卖给谁、怎么自我定位** | 一句话 + 典型买方角色 | ⭐ 只写**对方官网/招标文件里的话**，不写我们的解读 |
| **3** | **我们会在哪遇到他** | 细分 + 金额区间 + 采购方式（公开招标 / 比选 / 单一来源） | ⭐ **必须区分"公开招标"和"单一来源"**：单一来源 = 客户已内定，我们几乎无法进入 → **card 里要标"此场景不可赢"** |
| **4** | ⭐ **他们为什么被选中（诚实版）** | 客户真实选择理由：品牌、已有生态集成、审签历史、人员熟练度、价格、既有合同 | ⭐ **必须有这一格，否则销售会扔掉 card**（任何假装竞品没有优点的 battlecard 都会被销售扔掉） |
| **5** | **我们强在哪（3 条，每条带证据 + 一句话话术）** | 差异化 + 证据（客户案例 / 对标数据 / 演示时刻）+ 销售能直接说的一句话 | ⭐ 证据分四档：**🅐 多源 / 🅑 厂商单源+具名客户 / 🅒 含自证循环 / 🅓 不可核验** |
| **6** | **他们强在哪（诚实）+ 我们的回应** | 承认 → 再重构到"对这个买家重要的事" | ⭐ **CAE 特有最强项**：他们的强项通常是"**20 年算例库 + 全行业人员都会用 + 审签历史**"——**这三条我们短期赢不了，只能重构为"新问题/旁路场景/AI 加速"** |
| **7** | **Landmine questions（3 条）** | 让买家自己说出对我们有利的真相的开放问题 | ⭐ 例："你们上一次因为算例库和历史结果对不上而重算，是什么时候？""你们上次做试验对标，是几年前的数据库？""新的型号如果沿用老工具，谁来验证新材料本构？" |
| **8** | **Objection handling（他们会埋的 3 个雷 + 回应 + 证据）** | 逐条：他们的说法 → 我们的回应 → 可给客户看的证据 | ⭐ 必含三条 CAE 标准雷：**"国产精度不行"**（回应：对标 NAFEMS 基准集）、**"国产没案例"**、**"数据出域"**（回应：内网物理隔离部署） |
| **9** | **定价与打包** | **只写他们公开的价**（公开价目 / 招标公告价）+ 来源链接与日期；未公开写"未公开" | ⭐ **红线**：不得写"听说他们卖 X 万" |
| **10** | **折扣护栏 + ⭐ 何时该放弃** | 销售可给的折扣上限、谁批超限；⭐ **"这单我们该退出"的画像** | ⭐ 没有"何时放弃"这一格，card 就只是一份攻击话术 |
| **11** | **升级联系人 + 证据资产索引** | 找谁问（PMM / SE 负责人 / 竞品频道）+ 可直接发客户的证明材料链接 | ⭐ 让 card **可被销售当场调用**，而不是一份要读的文档 |

## 1.2 什么时候用、给谁用、放在哪

| 项 | 内容 |
|---|---|
| **什么时候用** | ⭐ **不要在做市场规模时做，要在做销售赋能与定位校准时做** |
| **给谁用** | 一线销售/售前（主用户）、产品营销（owner）、PM（当 roadmap 输入） |
| **放在哪** | ⭐ **放在 CRM 里 + 竞品页面上，不放在 Wiki**。放在 Wiki 的 battlecard 三个月后没人看（只更新文档不培训，"battlecard 不会被使用"） |
| **更新节奏** | 每次 win/loss 复盘后触发；**新版本发布、涨价、并购、竞品政策变化、连续 2 次被销售纠正** → 触发复核 |
| **红线** | 无证据的优越性表述不得进 card；每个比较性陈述要有"**原话、来源 URL、发布方、日期、适用范围、状态、owner、失效期**"的 **claim ledger**；敏感话题（安全、客户数、定价、路线图、性能）**每条配一行 "do not say"** |

# 二、⭐⭐ Win/Loss 分析

## 2.1 ⭐ 怎么收集（必须有真实记录，不是推测）

### 三条数据流，缺一不可

| 流 | 来源 | 采集方式 | 数量要求 | 置信度 |
|---|---|---|---|---|
| **① 内部记录** | CRM（金额、阶段、输在哪个阶段、记录的输因、竞品标签）+ 邮件/通话纪要 + 投标文件 | ⭐ **先清洗 CRM**：修缺失 close reason、修错竞品标签。⭐ **"如果 30% 的单竞品字段是 unknown 或空，按竞品分段的 win rate 就不可用"** | 全部已决单 | 🟡 销售自述有系统性偏差（爱甩锅给价格） |
| **② 买方访谈** | 赢单 + 输单 + ⭐ **无决策单** | ⭐ **三种结局都要访谈**（只访输家是常见错误）。时机：赢单在成交后 30 天内最容易约到（实施蜜月期）；输单在决定后 30–60 天内；无决策单最难约但**通常最有启发性** | 首轮 10–20 单，加权偏向 Step 1 的目标细分 | 🟢 **最高** |
| **③ 渠道/第三方** | 代理商、VAR、仿真外包服务商 | 他们听到的输因 | 持续 | 🟡 |

### 访谈执行规范（工业软件版）

| 规范 | 内容 |
|---|---|
| **谁去访** | ⭐ **不能是原 deal owner**——买家会对卖过他的人软化反馈。由 PMM / 售前负责人 / 产品负责人去 |
| **怎么开场** | "我们正在改进流程，希望得到您 20 分钟坦诚反馈，**没有销售意图**" |
| **时长/激励** | 20–30 分钟；小激励（礼品卡/捐其偏好的公益机构） |
| **赢单问题** | "请带我回顾您是怎么做这个决定的？谁参与了？关键标准是什么？""**是什么差点让您选了别的？**" |
| **输单问题** | "他们做了什么是引起共鸣的？""**他们有没有向您展示我们没展示的东西？**""这个决定主要是关于产品、团队，还是其他？" |
| **无决策问题** | "是什么让这件事停下来的？预算冻结？内部优先级？" |
| **禁止** | 不反驳（即使不公平）；不试图重启交易；⭐ **不用引导问题**（"所以您会说我们的产品最好，对吧？"） |
| ⭐ **CAE 专属追问** | "他们有没有提供**试验对标报告**？""他们提供的结果**你们签字的人接受吗**？""上线后实际用的算例是他们的还是你们的？""有没有出现过结果不一致，你们怎么处理的？" |

## 2.2 ⭐ 核心指标：win rate 怎么算才不被质疑

```
竞争 win rate = Closed-Won ÷ (Closed-Won + Closed-Lost)
```

**⭐ 五个"不被质疑"的必要条件**：

| # | 规则 | 理由 |
|---|---|---|
| 1 | **分母排除 open（未决）单** | 未决单对 win rate 无信息量；混进去会人为压低 |
| 2 | ⭐ **分母排除 no-decision，单独列** | **25–40% 的已评估单以"no decision"收场**；no-decision 与竞争性输单成因不同（预算冻结/优先级变动），混在一起两个问题都看不清 |
| 3 | ⭐ **同时报两个数**：`竞争 win rate`（只算有明确赢家的）与 `全机会转化率`（含 no-decision）；并说明口径 | 把 no-decision 剔出后数字会高 **10–15 个百分点**——**两个数都报才不会被质疑"你在挑算法"** |
| 4 | ⭐ **分段报，不报总数** | 总体 30% 可能掩盖中端 55% / 大客户 12%；不同细分需要完全不同的打法 |
| 5 | **时间窗用滚动 12 个月** | 2025-01 关的单反映的是 2024-Q3 启动的过程；滚动窗口更稳定 |
| 6 | ⭐ **win rate 必须与量指标并排看** | **win rate 上升可能只是"我们变挑了"（提前 disqualify 弱单）**，不是竞争能力变强 → 必须同时看 opportunity 总量与 pipeline coverage |

**基准（参考，非目标）**：B2B SaaS 整体 win rate 15–30%；有明确竞品的竞争 win rate 35–50%

### ⭐ CAE 领域的特殊修正

| 修正 | 说明 |
|---|---|
| ⭐ **"输给的竞品"必须区分真竞品与伪替代** | ⭐ **工业软件大量输单是输给"不做"**（客户决定不做了/用 Excel/继续用旧工具/外包）。把 no-decision 和"输给伪替代"混进"竞争性输单"，会得出"我们输给 Ansys"这种**完全错误的结论**，从而把资源投到错误的战场 |
| ⭐ **"中标但不是我们想要的项目"单独标记** | ⭐ 定制开发单中标（毛利率 30%）≠ 标准软件单中标（毛利率 95%）。**win rate 和"标准软件单 win rate"必须并报** |
| ⭐ **区分首单与复购** | ⭐ **复购 win rate 是产品价值的直接度量**，比首单 win rate 更可信 |
| ⭐ **记录"输在哪个阶段"** | 输在"技术要求"= 产品/资质问题；输在"评分"= 商务/关系问题；输在"废标"= 资格问题。**三者的解法完全不同** |

## 2.3 ⭐ "为什么输给对手"最常见的 7 个真实原因（CAE 版）

| # | 原因 | 真实世界表现 | 解法方向 |
|---|---|---|---|
| **1** | ⭐ **切换成本 / 资产沉没** | "我们有 15 年的算例库和材料数据，换掉要重新审签" | 做旁路/新场景；提供数据导入桥（⭐ Persistent ID / STEP 意图传递，CAx-IF v1.8）；⭐ **把"不替换"设计成产品特性** |
| **2** | ⭐ **可签字性 / 审签体系缺失** | "结果算出来，但总师不认，因为没有归档格式和责任链" | 交付"报告 + 过程可追溯 + 归档包"；做**签字模板**；⭐ 引入"CAE 工程师在摘要页签字 + 网格无关性 5% + 试验对标" |
| **3** | **资质/合规/信创不满足** | 涉密项目要纯内网物理隔离 + 信创目录 + 保密资格；85% 装备制造企业拒绝核心设计数据上云 | 提前做信创适配 + 密评；⭐ **把"数据不出域"做成销售第一页** |
| **4** | **已有合同周期未到 / 已被集团统购** | "我们集团 2024 年刚签了 Ansys 三年" | 切"新场景"（AI 加速、几何 healing、验证环节）或切子公司/院所在**下一个预算周期** |
| **5** | ⭐⭐ **被"所内自研"击败** | 实证：2026-05 航空工业电子结构强度仿真软件，**中国飞机强度研究所（自研）以 420 万、98.19 分中标第一** | ⭐ **这是最被低估的对手**。对策不是比功能，是**做自研做不到的部分**（跨所复用、多物理、平台化、AI 加速）或**成为自研的底座**（卖给他们而不是替代他们） |
| **6** | **预算科目错配 / 卡在财务流程** | 订阅被归 OpEx 而客户只有 CapEx 空间；或软件采购卡在"没有这个科目" | ⭐ 提供买断选项 + 把服务费拆进现有科目；**先卖能进预算科目的东西（服务/外包），再切许可证** |
| **7** | **技术方向不对** | 客户要电磁/流体多物理，而我们是结构强项 | 承认并退出，或找交叉点（结构-热耦合、结构-电磁） |

> ⭐⭐ **注意 #5**：它不是"传统巨头"，是**用户自己**。在 CAE 领域这是最真实的对手之一，
> 且《竞品地图》里大概率没有它。**建议在 win/loss 表里单设一列"输给了客户自研"。**

# 三、⭐⭐ 竞品情报的合法与高效采集

## 3.1 什么能问、什么不能

| 来源 | ✅ 可以 | ⛔ 不能 / 红线 |
|---|---|---|
| **客户** | 问他们的**决策过程、评分标准、感受**：为什么选他、他的报价在哪个区间、你们比较了哪几家、评分表怎么分、我们输在哪 | ⛔ 让他**转述对方的保密报价单/合同细节**；⛔ 让他代我们向对方打探；⛔ 冒充采购 |
| **客户（深度访谈）** | 问"**他给你看了什么**"（竞品的**演示内容/方法论/交付物形态**）——这是**竞品的产品情报**，不是商业秘密 | ⛔ 索取其报价单原件 |
| **前员工 / 跳槽员工** | ✅ 问**通用技术栈与工程实践** | ⛔ 索取**源代码、未公开路线图、客户名单、未公开报价**。⚠️ 竞业限制与保密协议可能覆盖；**我们作为接收方也有风险**（诱导违约） |
| **渠道 / 代理商** | ✅ 问他们**从我们这走单还是从对方走单**，输在哪 | ⛔ 让他们做"双面间谍"去获取对方内部报价 |
| ⭐ **公开招标公告** | ✅✅ **完全合法、完全公开**：中标价、投标人数、评分办法、技术要求、交付周期 | — |
| **招聘 JD** | ✅ **完全合法**：岗位类型、技能栈、汇报关系、办公地 | — |
| **专利 / 论文** | ✅ **完全合法**：申请时间、权利要求、技术路线方向 | — |
| **产品试用 / Demo** | ✅ 亲自试用、拆解公开 Demo、读公开文档 | ⛔ 破解授权（环境变量绕过许可检查、网盘"免费版"） |
| **官网 / 定价页 / 文档** | ✅ 完全公开 | — |
| ⛔ **红线区** | — | **冒充采购下单**、**窃取报价单**、**收买对方员工泄密**、**逆向破解授权**、**违反保密协议的转述** |

> ⭐ **冒充采购还可能构成虚假采购**，触犯《招标投标法》《反不正当竞争法》；
> **军工涉密场景后果尤其严重。**

## 3.2 ⭐⭐ 从招标文件反推竞品（最被低估的合法情报源）

> **为什么这是金矿**：招标文件是**客户写给"某个他们心里已有或想要的方案"的文本**。
> 它必须满足"足够具体以排除虚假响应"，又"足够开放以不构成排他"
> （受《政府采购需求管理办法》约束：需求调查对象一般不少于 3 个且具代表性）。

### 五步读法

| 步 | 读什么 | 推断什么 |
|---|---|---|
| **S1 读项目背景与采购动机** | "为什么是现在？"（立项号、预算来源、上一次采购为什么没成） | **客户是"更新换代"还是"首次建能力"** |
| **S2 读技术要求书的"术语指纹"** | ⭐ **技术路线暗示** | **谁的技术路线**（见下表） |
| **S3 读评分表权重分布** | 技术分/商务分/价格分比例 | **客户到底在乎什么**（技术分占比显著高于常规 → 通常存在意向合作单位） |
| **S4 读资格条件** | 是否要求特定认证、是否限定业绩范围 | **竞争者池的大小**（限定特定行业/客户项目经验 → 人为缩小竞争范围） |
| **S5 读交付与验收条款** | 交付周期、试运行时长、资料交付要求 | ⭐ **竞品的服务能力画像** |

### ⭐⭐ 术语指纹对照表（核心增量）

| 技术要求里出现 | 强烈暗示的竞品技术路线 | 推理链 |
|---|---|---|
| "**基于网格的**""单元类型""**网格无关性**""**网格收敛性验证**" | Ansys / Abaqus 家族（FEM 传统路线） | 只有 FEM 路线需要强调网格无关性 |
| "**CAD 内直接**""**装配 mates 直接变运动学**""**无中间文件**" | SimSolid / MODSIM / Onshape Simulation 路线 | ⭐ 真正做到这一点的只有 3 家 |
| "**降阶模型 / ROM / 代理模型 / 神经算子**""**在线实时预测**" | PhysicsX / 51WORLD / 索辰开物类 | ⭐ PhysicsX 是国际可比对象，51WORLD 是 AICube 的对标 |
| "**纯几何输入 / 不建网格**""**无网格**" | SimSolid 明确路线 | — |
| "**材料库 / 材料本构库**""**参数化本构**" | 索辰（军工自研 + 收购欧洲电磁） | — |
| "**Python / MATLAB 脚本接口 / API 二次开发**" | 开放接口型（Ansys APDL / Abaqus Python / COMSOL） | — |
| "**HFSS / 全波 / 电磁场**""**天线 / PCB**" | Ansys HFSS / CST / 索辰 WIPL-D | — |
| ⭐ **"自研求解器 + 国产化底座**""**自主可控**" | **国产替代采购包的红利词**——同时意味着竞品是国产厂商 | ✅ 中物院公告原文："本项目拟基于**国产自主的 CAE 软件底座**" |
| "**信创 / 麒麟 / 达梦 / 鲲鹏**""**纯内网 / 物理隔离 / 数据不出域**" | 军工/涉密采购包 | — |
| "**编校 / 归档 / 追溯 / 三员管理 / 密级标定**" | 军工质量体系采购包 | — |

# 四、⭐⭐⭐ 定位图（positioning map）的正确画法

## 4.1 哪些轴能撑住 / 哪些轴是伪差异

| 判据 | ✅ 能撑住的轴 | ⛔ 伪差异轴 |
|---|---|---|
| **来源** | ⭐ **来自客户语料**：win/loss 访谈里反复出现的对比轴、客户自己排序的维度 | 我们内部认为的优势（"AI 能力强"、"架构先进"） |
| **可评分性** | 客户能一致地给 1–10 分 | 客户说不清两家差在哪 |
| **区分度** | 能把主要竞品分开 | 所有品牌挤在一角 |
| **可防御性** | 我们能持续占住 | 占不住的（对手 6 个月内能追平） |
| ⭐ **反例识别** | — | ⭐ **"我们说自己好但客户不这么排"= 典型伪差异**。检测：把我们自认的 3 个优势做成卡片让客户排序 → 若排序与我们的叙事冲突，**这条轴就是伪差异** |

### ⭐ CAE 领域候选轴（按可信度排序）

| 轴 | 可撑住？ | 依据 |
|---|---|---|
| ⭐ **"敢签字 / 结果可归档" ↔ "结果仅供参考"** | 🟢 **最撑得住** | 直接对应客户最强痛点；有客观判据（客户签字流程、归档规范） |
| ⭐ **"几何鲁棒性 / 网格无关性" ↔ "需专家手工修几何"** | 🟢 撑得住 | 客观指标（失败率、单元数比、核时比）：3 小面+1 小缝 → 单元数 2×、核时 4× |
| "迭代速度" ↔ "算完一版要一周" | 🟡 中 | 速度易被单点 benchmark 操纵；应用"是否加速到 10×"这种硬问题 |
| "部署形态：内网物理隔离 ↔ 必须云" | 🟢 撑得住（对中国军工/医疗） | 客观二元 |
| "模型覆盖广度" ↔ "单学科" | 🟡 中 | 可撑但易被"我也能加个模块"反击 |
| ⭐ **"AI 能力" ↔ "无 AI"** | ⛔ **伪差异轴** | ⭐ 客户不按此排序（Kano：AI 在 CAE 客户侧很可能是无差异型）；且客户会问"AI 准不准" → 立刻回到确定性问题 |
| ⭐ **"能否导入 STEP"** | ⛔ **伪差异轴** | 所有 CAE 都能导 STEP → 无区分度 |
| "价格" | ⚠️ **慎用** | 易理解但不易区分 |

## 4.2 ⭐ 如何避免"右上角空无一物"

### 空白格的三种解释（必须区分）

| 解释 | 判断方法 | 处置 |
|---|---|---|
| **真机会** | 客户确实重视这个组合，且我们能占住 | 攻 |
| ⭐ **轴选错了** | 客户从不这样比较 | 重选轴 |
| ⭐ **市场不存在** | 那个组合没人要（无需求） | 放弃 |

### 三个防御动作

| # | 动作 | 说明 |
|---|---|---|
| **D1 先锁轴，再看结果** | ⭐ **最危险的错误是"看到结果后再改轴"**——换竞品、换属性、换刻度，总能把自己挪到想要的象限。**事前写下"为什么选这几个品牌、这几个属性、给谁看、用于什么决策"** | — |
| **D2 空白格三问** | ① 客户真的想要这个位置吗？② 我们能守住吗？③ 优势可防御吗？**三个都"是"才是机会** | — |
| **D3 聚焦竞争集** | ⭐ **只放客户真正同时比较的 5–10 个品牌**，不放全行业。B2B 竞争集要窄。⚠️ 并且 **B2B 的替代方案不只有软件**：还有 Excel、人工、外包、⭐ **什么都不做**——⭐ **把"什么都不做"画进图里**，否则会画出客户根本没在考虑的一张图 | — |

## 4.3 ⭐ 三种图必须分开（最容易混的地方）

| 图 | 数据来源 | 用途 | 典型误用 |
|---|---|---|---|
| **内部竞争图** | 管理层假设 + 案头研究 | **形成假设** | ⭐ 拿它当"市场地图"给投资人 → 被拆穿 |
| ⭐ **感知图（perceptual map）** | ⭐ **目标客户的调查/访谈**（评分、相似性判断） | **测量市场怎么看** | 用内部认知代替客户感知 |
| **竞争数据图** | 价格、功能、覆盖率、交付性能 | **描述可观测特性** | 用它推断感知 |

> ⭐ **方法论纪律**：**感知图的轴来自 win/loss 研究**（不是头脑风暴）；
> ⭐ **感知图暴露"市场怎么看"，竞争分析暴露"实际能做什么"，win/loss 解释"两者的差距"**。

### 采样与画法（B2B 可操作）

| 项 | 建议 |
|---|---|
| 竞品集 | 客户真实比较的 5–10 个 |
| 轴数 | 2（最多 3） |
| 受访者 | B2B 实用下限 **50–100 人**（压掉异常值、稳定均值） |
| 评分方式 | 让真实买家给每个品牌每条轴 1–10 分 |
| 降维方法 | 候选属性多时用 MDS / 因子分析 / 对应分析，⭐ **而不是拍脑袋选** |
| ⚠️ 禁止 | ⭐ **在看到结果后改轴**；把内部图当感知图 |

# 五、⭐⭐ Feature Matrix 的正确做法与陷阱

## 5.1 ⛔ 陷阱：不要做功能清单

| ❌ 功能清单（客户不按功能买） | ✅ 正确的维度 |
|---|---|
| "支持非线性材料 / 支持二次单元 / 支持 CFD 耦合" | "**解决什么问题 + 客户付出什么代价**" |
| 有/无勾选表 | "**客户原来要做什么 → 现在要做什么 → 中间省了什么 / 冒了什么风险**" |

## 5.2 ⭐ 正确的 Feature Matrix 结构（CAE 版）

| 维度 | 提问 | 填写内容 |
|---|---|---|
| **① 客户要完成的任务** | 客户拿这套工具是为了完成什么工作？ | "算复材层合板在 [工况] 下的 [失效模式] 并出可归档报告" |
| **② 客户原来怎么做（代价）** | 现在的方式 | 手工网格 + 手工修几何 + 外包 + 试验验证 |
| **③ 原来的代价是什么** | 时间 / 人 / 钱 / 风险 | ⭐ **要具体到数字** |
| **④ 用我们之后** | 改变 | 步骤少了几个、几何失败率降多少、报告可直接归档 |
| **⑤ 迁入成本** | 换过来要付出什么 | 数据迁移、算例迁移、培训、审签流程改造、⭐ **可签字性建立** |
| **⑥ 客户仍需自己做** | 剩下什么 | ⭐ **必须诚实写**——CAE 客户极其敏感于"你替我干了但我要担责" |

> ⭐⭐ **为什么这个结构在 CAE 尤其重要**：
> 因为 CAE 的采购决策**不是"买功能"，是"买一个能签字的结果"**。
> 所以矩阵里最该被填满的是 **③ 代价** 和 **⑥ 客户仍需自己做**——
> 这两列决定了诚实的客户能不能接受你。

## 5.3 ⭐ 三个 CAE 特有的"客户代价"指标

| 指标 | 定义 | 现有基线 |
|---|---|---|
| ⭐ **几何失败率** | CAE 流程中因几何缺陷直接失败的算例比例 | **80% 源于几何缺陷** ✅ |
| ⭐ **修复放大系数** | 一个小缺陷导致的单元数/核时放大倍数 | 3 小面+1 小缝 → 单元数 2×、核时 4× ✅ |
| ⭐ **签字前置工作量** | 从有结果到能签字，还需要几个人天/几道流程 | ⭐ **我们最该测、也最少人测的指标** |

# 六、⭐⭐ 竞品的"叙事"与"实质"要分开拆

> **方法**：把每家竞品拆成两栏——**它嘴上说的** vs **它实际做的**——然后问"**这个差异为什么对我们有利**"。

| 竞品 | 嘴上说的（叙事） | 实际做的（实质） | ⭐ 差异对我们有利在哪 |
|---|---|---|---|
| **① 索辰科技** | "物理 AI 平台"、"具身智能虚拟训练"、"低空三维地图"（2025-10 投资者关系表述 ✅） | ✅ 2024 年主营仍为**工程仿真软件 2.28 亿（占主营 >60%，毛利率 >95%）+ 仿真产品开发 1.37 亿（毛利率 ~30%）**；物理 AI 收入 25 年中报 0→1，占比 **6.5%** ✅ | ⭐ **它的收入主体仍是传统 CAE 卖软件**（95% 毛利那部分），物理 AI 是叙事增量。→ **它不会为了一个新范式推翻自己的标准软件模型 → 我方"旁路/模块"策略正好卡在它最不想动的位置**；且它仿真产品开发毛利仅 30% ✅ → **在需要定制的项目上它比我们更贵**。⚠️ 但**它做物理 AI 是认真的**（开物 2025-02、机器人虚拟训练 2025-07） |
| **② 云道智造 / 云道智能** | "国产自主多物理场云仿真平台"、"电子散热仿真第一"（14.9% 份额，超 Cadence/Ansys/西门子 ✅） | ✅ 实际交付形态是**大量中小额单点中标**：钣金成形 68 万、恒驰中兴 35 万、清华核安全 143.9 万；在航空工业电子结构强度项目**排第 7（90.94 分）** ✅ | ⭐ **它强在单点、专场景、小额；弱在主机厂主力大单**。→ **2026-05 那份 420–435 万单它进不了第一梯队。若我方主战场是中大型结构强度主力模块（150–350 万），它不是主要对手**；它在**电子散热**是真正对手 → **别在它主场打**。另：它 2026-03 拿下清华核安全（**单一来源** ✅）→ 单一来源 = 关系型优势，不是技术优势 |
| **③ Ansys** | "AI 虚拟助手 AnsysGPT"、"多物理场"、"行业标准" | ✅ 真实生态锁定极深：Mechanical 永久授权 30–80 万、10 并发比单用户贵约 3 倍、HPC 每核 add-on 约 $5k、学术授权仅 ~$275（≤4 核）✅ → **学术→工业的人才与代码路径锁定** | ⭐ **它嘴上说 AI，实际卖的是装机基础与切换成本**。→ 这正是"替换成本轴高"象限 ② 的成因——⭐ **我们不该替换它，该在它没覆盖的场景（几何 healing、AI 加速、试验对标、验证环节）插入**。另：**它的学术低价策略培养了我们的工程师用户**——这对我方是**利好** |

> ⭐⭐ **三条可复用的结论**
> 1. ⭐ **"AI/物理 AI"在中国工业软件里目前普遍是叙事层，收入主体仍是标准软件**（索辰物理 AI 占比 6.5%）。→ **不要被对手的叙事牵着改自己的定位**；坚持"**把 AI 定义为迭代速度提升一个数量级，不是替代求解器**"
> 2. ⭐ **"平台化"目前主要体现在交付形态与金额结构，不等于客户已接受订阅** → **平台化叙事 ≠ 商业模式已切换**，不要拿它推预算周期
> 3. ⭐ **"国产化率高"（36%）与"国产份额低"（21.7%）并存，说明"国产"内部已经分层**：真正有内核的不足 15 家 ✅。→ **市场在出清，伪国产厂商会先死，留下的客户更愿意给真国产机会。但同时说明：我们不能靠"国产"这个标签卖，只能靠"能签字"卖。**

# 七、⭐ 竞品情报的纪律清单

| # | 纪律 | 理由 |
|---|---|---|
| 1 | ⭐ **所有比较性陈述进 claim ledger**（原话、来源 URL、发布方、日期、适用范围、状态、owner、失效期） | 无出处的比较 = 定时炸弹 |
| 2 | ⭐ **敏感话题每条配一行 "do not say"** | 安全、客户数、定价、路线图、性能 |
| 3 | ⭐ **从招标文件反推优先于看竞品官网** | 招标文件是客户心里那个方案的语法 |
| 4 | ⭐ **每 5 场访谈做一次差异化排序审计** | 排序与我们的叙事冲突 → 我们进错了细分 |
| 5 | ⭐ **每个季度回看 win/loss 里"输给了客户自研"的占比** | ⭐ **这是被低估的对手** |
| 6 | ⭐ **对竞品宣传数字一律标可核验性等级** | 🅐/🅑/🅒/🅓 |
| 7 | ⭐ **竞品 card 超过 6 个月未复核 → 作废** | CAE 竞品迭代极快 |
| 8 | **红线**：冒充采购 / 窃取报价单 / 收买泄密 / 破解授权 | 法律与声誉风险 |
