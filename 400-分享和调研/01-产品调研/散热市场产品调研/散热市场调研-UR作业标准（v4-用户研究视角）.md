# 散热（热管理）领域调研 · 专家作业标准 v4（UR 视角）

> **这一版换了一双眼睛。**
> v1 战略层（值不值得进）→ v2 执行层（一天怎么排）→ v3 专业层（专家会做什么）→ v4 三兄弟（**MR 财务视角** / **仪器方法视角** / **投资尽调视角**）。
> **本文件是第四个视角：UR（用户研究 / 用研 / 产品线 / 设计中心）。**
>
> **UR 的问题不是"这个市场多大、钱在哪、怎么排期"，而是——**
> **"使用这个产品的人是谁？他一天怎么过？他说的词和我说的词是不是同一个东西？他凭什么敢在报告上签字？他不信我的时候，我拿什么让他信？"**
>
> **本轮真正的新增量：前面三版都把"抓 JD 词频"写成了一条待办动作；这一版把它做完了，并取回了第一批工程师本人的自述。**
> 所以本文件是**四版里唯一有"人的一手声音"的一版**。

## 1. 前提校正：UR 视角的三个"如果错了，后面全废"

> MR 校正的是"坐标系"（器件级 → 机柜级）；UR 校正的是**"我们以为在跟谁说话"**。

### 1.1 校正一：客户不是一家公司，是同一张桌子上的四个互不信任的人

**不做这一步的代价**：会得出"客户需要更准的模型"——然后发现每个角色要的东西都不一样，且**互相反对**。

| 角色 | 他真正要的 | 他最怕的 | 他会否签你的报告 | 一手证据 |
|---|---|---|---|---|
| **热设计工程师**（用工具的人） | 快速出一个"能站得住"的结果 | 被硬件/结构挑战、被老板追问 | ✅ 唯一签字人 | 「你要降规格！」（华为真实事件） |
| **结构工程师**（被要求兼做热） | 尽量少改结构 | 改结构 = 改模具 = 延期 | ❌ | 「结构工程师一开始可以尝试一些初步的热仿真」 |
| **硬件工程师**（给功耗的人） | 少改降额方案 | 降规格 = 砍性能 | ❌ | 「我仿过了？」「**我用脑袋仿过了，你过不了**」 |
| **签字/评审的 leader** | 结论可追溯、别背锅 | 出事被追责、被审计 | ✅✅ 真正的决策人 | 「**AI 无法在报告上签字，无法在法庭上为其错误导致的工程事故负责**」 |

⭐ **UR 判定**：**产品的使用者是热设计工程师，但付钱和否决的可能是 leader，而真正卡住项目的往往是结构/硬件给不出输入。**
→ 所以调研问题不是"你要什么功能"，而是"**你在哪个环节没有别人给你的输入**"。取证实锤：热设计在概念设计阶段存在"**信息时间差**"——要拿 3D 结构图、元器件布局、功耗，而此时结构与硬件未必给得出（fangzhenxiu.com/post/2241584）。

### 1.2 校正二：竞品不是 Ansys，是「Excel 速算表 + 台架 + 一个不信仿真的老板」

**不做这一步的代价**：会以为竞品是 Flotherm/Icepak（JD 词频里它们确实占 43.6%），然后把产品做成"更快的 Flotherm"，打一场必输的仗。

**客户真正的现有工具链（本轮实取）**：
```
【Excel 热阻网络 / 速算表】→【台架实测】→【台架报告】→【评审会】
        ↑ 私域沉淀，非公开下载            ↑ 唯一硬标准        ↑ 签字发生地
        └─ 行业惯例：10 节点(45项热阻)后维护成本反超收益
```
一手证据：
- **Excel 表格真实存在于工程师私域**：「这个其实有个 excel 表格，在 VIP 群还有我们知识库里面存放」；还有商业化的《车神》热设计计算模板（￥9.9，含散热器/热阻/风阻/噪音/风量/通风孔公式）
- **Excel 有公认天花板**：10 节点 = 45 个热阻、20 节点 = 190 项，「Accurately entering this many values…would likely require effort significant enough to overwhelm the benefits」——**这正是 FEMAI 该接的位置：不是取代 Excel，而是接住它接不住的规模**
- **硬标准是台架不是仿真**：「**热测试是最终验证设计方案是否通过的根本标准**」

⭐ **UR 判定**：**FEMAI 的真正竞品是"没有仿真"这个选项（加余量设计 / 拉长周期 / 花钱做台架）**，不是 Ansys。所有功能对比表都是错的战场。

### 1.3 校正三：AI 采纳的瓶颈不是精度，是"谁签字"和"哪个数字能被审"

**不做这一步的代价**：会得出"精度提高 X% 就能卖"，然后发现客户根本不看你那个数字——他们看的是**能不能解释偏差**。

**本轮取回的中国一线口径**：
- **可接受误差**：工程上通常 **±5%~±15%**（关键温度点要求更高）——一线工程师自己的话
- **未校准 vs 校准后**：某车载逆变器项目，**未校准模型平均误差 9.3℃，校准后稳定在 1.2℃ 以内**（blog.csdn.net/weixin_32612263/article/details/162058585）——**这才是"值不值"的答案，不是快多少倍**
- **校准有优先级共识**：先对流换热系数 h → 再热源功耗 → 再接触热阻 → 最后材料属性；且「**校准不是"硬凑"数据**」
- **致命警告**：「**没有不确定性量化的 AI 仿真工具，生产环境里建议谨慎使用**」

⭐ **UR 判定（可辩护的立论收紧）**：
> **不是"我们的仿真比 Excel 准"，而是"在 k≈0.5 W/(m·K) 的结构件里，界面热阻与展热路径本身就是待设计的未知量，而热阻网络要求你预先给定它"——这是 Excel 在原理上不可解、FNO+CHT 可解的唯一缺口。**
> 并且：交付物必须包含**可追溯的不确定度边界**，否则中国场景无法替代求解器。

## 2. 任务一：顶尖用研专家会额外开展、而本次没要求的工作（22 项）

> 判定标准同前：**不做会得出什么错误结论**。
> UR 特有的三组：**A 找对人 / B 看见真实工作流 / C 建信任与可用性**（MR 与投资视角不覆盖 B、C）。

### A. 找对人（6 项）——把"客户"这个伪概念拆掉

| # | 专家动作 | 不做会得出什么错误结论 | 具体怎么做 |
|---|---|---|---|
| **A1** | ⭐⭐ **用 JD 代替访谈做"用户能力画像"** | 会相信访谈里的话。工程师在客户面前会配合你，但**招聘要求不会配合你** | 实取 39 条 JD（见 §3.2），按软件词/脚本要求/一维建模要求建**能力矩阵**。JD 是"用户画像的公开代理变量" |
| **A2** | ⭐⭐ **做"角色冲突图"，不只做客户分层** | 会以为搞定技术人就搞定客户 | 画出四个角色（§1.1）之间的**否决权与冲突点**：热设计 vs 结构（改模具）、热设计 vs 硬件（降规格） |
| **A3** | ⭐ **专门找"说不需要"的人** | 只会听到愿意聊的人，得出"需求普遍存在" | 主动找：说"Excel 就够"的人、说"仿真没用"的人、已离职的仿真工程师、**近 3 年从仿真岗转走的人** |
| **A4** | ⭐ **取"非幸存者"样本** | 会以为中国散热工程师普遍在用 CFD | 本轮发现：可被检索到的自述几乎全来自**做培训/做自媒体/做售前**的人（既是知识生产者又是卖方）。**必须补纯执行岗样本** |
| **A5** | ⭐ **区分"使用者画像"与"购买者画像"** | 会把采购决策人当用户访谈 | 用户 = 热设计工程师（用）；付费者 = 老板/采购；否决者 = 结构+硬件+评审。**三张画像分开画** |
| **A6** | ⭐ **量一量"团队密度"** | 会高估单点切入的杠杆 | 本轮实取：立敏达"研发团队及项目管理团队目前有 40 余名"、云道智造"研发人员占比 70%，硕士占比 90%，博士占比 30%"、"CAE 岗武汉招 20 人"。**团队规模 = 内部推广的阻力也是杠杆** |

### B. 看见真实工作流（8 项）——这是 UR 最不可替代的一组

| # | 专家动作 | 不做会得出什么错误结论 | 具体怎么做 |
|---|---|---|---|
| **B1** | ⭐⭐ **做"情境访谈"而不是"回忆访谈"** | 会拿到理想化的流程描述（"我建模→仿真→写报告"），而真实流程里有一半时间在**等别人给输入** | 到客户工位旁观察 1 次真实项目（2h），记录：等了谁、等了多久、收到的是什么格式 |
| **B2** | ⭐⭐ **抓"信息时间差"** | 会以为客户是"有需求没工具" | 概念阶段：热设计要 3D 结构图/元器件布局/功耗，而此时结构硬件给不出。**调研必须问"你在等谁"** |
| **B3** | ⭐⭐ **复原"翻车"全过程，而不是问"你遇到什么困难"** | 会得到抽象抱怨（"建模太难"）而不是可修复的环节 | 拿 3 个真实翻车案例做时间线复盘：灿途大灯案例是范本（仿真 110℃ / 实测 128℃ / 偏差 18℃ → 定位到导热硅脂 3.5→1.2 W/m·K） |
| **B4** | ⭐⭐ **读"客户自己的"文档：报告模板与内部 wiki** | 会按我们的格式设计输出，客户根本不用 | 本轮实取到企业**内部技术 wiki 公开页**（铭普光磁）——含真实链路规则：CAD→SCDM→Icepak；Icepak 直角流道会不收敛；Flotherm 复杂几何须过 FloMCAD 否则"导入时间很长，导致电脑崩溃" |
| **B5** | ⭐ **数一数客户真正的"日常工具"** | 会高估 Excel 的落后程度 | 看清：热阻网络 Excel + 数据验证限值 + 模拟运算表扫敏感性 + 私域知识库。**Excel 的强项是"锁参数"，不是算** |
| **B6** | ⭐ **观察"工具链切换点"** | 会误以为客户用一个工具端到端 | 中国工程师**按阶段切工具**：概念/趋势用 FloEFD·Flotherm → 详细用 Icepak·COMSOL·Star-CCM+ → 高精验证用 Fluent·Star-CCM+。「这要求仿真工程师同时掌握多款工具，在不同阶段灵活切换」 |
| **B7** | ⭐ **量学习曲线（不是问"好不好用"）** | 会拿到"还行"这种无效回答 | 用三档可测量基线：① 官方课程规模（Icepak 160 讲/1 天 10h55m/播放 10 万/学员 1000+；入门课仅 6 讲/1h37m）② 国产工具真实上手（云道 Simdroid：**两天集中培训 + 十多名工程师 + 核心熟练 3~4 周**）③ 环境配置成本（Ansys License/中文用户名/图形卡 **平均 2.5 小时/人**） |
| **B8** | ⭐ **看他的"工作台"：Excel 模型与报告骨架** | 会设计一个"工程上正确但用不起来"的界面 | 本轮实取：客户 Excel 的三大特征 = **最差情况参数（Rθjc 取手册 Max 而非 Typ）+ 数据验证限值 + 模拟运算表扫 Q**。UI 必须迁就这个习惯 |

### C. 建信任与可用性（8 项）——决定"报告能不能被签字"

| # | 专家动作 | 不做会得出什么错误结论 | 具体怎么做 |
|---|---|---|---|
| **C1** | ⭐⭐ **做"签字责任链"调研** | 会以为客户要"更准"，实际要"敢签" | 画出谁在什么文件上签字、签的是什么、错了谁担责。工程师自发造的《**参数真实性声明**》（逐条列参数来源/取值依据/偏差范围）——「**这份声明，比仿真云图本身更有价值**」 |
| **C2** | ⭐⭐ **做"盲测"式信任验证（不是问卷）** | 会用"满意度"这种伪指标 | 本轮取回的**唯一一条中国工程实践的 AI 采纳验证方法**：「把 AI 结果和传统求解结果混在一起请他们分辨，如果专家分不出来，那就说明模型达到了可用的信任水平」 |
| **C3** | ⭐⭐ **做"可解释性缺口"调研** | 会以为输出温度场就够了 | 工程师的原话是「**当结果异常时，工程师缺乏对其进行物理审校的抓手**」。必须问：结果异常时，你怎么办？答不出 → 产品缺的不是速度，是**归因工具** |
| **C4** | ⭐ **测"术语翻译损耗"** | 会用我们的词去访谈，客户听不懂、回答全是客套 | 本轮实取 12 类损耗（见 §3.4）。最危险的三个：**矾土(alumina)/铝(aluminum)**、**硅(silicon)/硅酮(silicone)**、**ψJT 不是热阻** |
| **C5** | ⭐ **调研"最恶劣工况"文化** | 会照客户现有做法做，反而 perpetuates 系统性原罪 | 本轮实取翻车根因：「**热仿真是按典型工况算的，根本没按最恶劣工况加满负载校核**」→ 设备半年内连锁失效。「**"能用"和"长期可靠"之间，差的就是那十几度结温**」 |
| **C6** | ⭐ **把"机器可读"当成产品的一部分来调研** | 会交付一个工程师没法归档的模型 | 本轮实取交付物清单（G 系列 JD 逐条）：仿真报告/测试报告/**仿真计算书**/DFM 报告/设计规范/**模型库**/**材料热物性数据库**/通用仿真模板/**归档**。「规范 + 模型库 + 归档」是岗位自带的三件套 |
| **C7** | ⭐ **问"标准怎么改"** | 会按现行标准设计，但草案正在变 | GB/T 2423.22 正在修订（采标 IEC 60068-2-14:2023），起草单位含**威凯检测、清深国际研究生院、中山大学**——**检测机构与高校在标准里，标准是可进的** |
| **C8** | ⭐ **调研"替代品"的心理账户** | 会以为客户在比价，其实客户在比"要不要花这个钱" | 客户心里有三级替代：**①Excel+加余量 ②花钱做台架 ③什么都不做**。仿真必须证明比第③项贵得值 |

## 3. 任务二：UR 会使用的原始一手素材（五环 + 本轮实取样本）

> **UR 的取材原则**：不看"行业说了什么"，看"**人做了什么、说了什么、存了什么**"。凡"应该怎么做"的表述，一律降级。

### 3.1 五环结构（按"离人的距离"）

```
环1 人的现场     工位上的Excel模型 · 报告模板 · 翻车件 · 私域知识库 · 微信收藏
环2 人的嘴       工程师自述 · 论坛讨论 · 内部wiki · 课程讲义 · 培训现场
环3 组织的印     JD原文 · 招标技术要求 · 8D · DFMEA · 年度预算表 · 会议纪要
环4 交易与监管   合同 · 中标公示 · 召回公告 · 判决书 · 标准正文 · 专利权利要求
环5 市场的声     厂商案例 · 代理商价目 · 云市场listing · 论文 · 公开benchmark
```

### 3.2 ⭐ 环1+环2 本轮实取清单（这是本文件的核心资产）

#### 环1：人的现场（真实存在、别人不公开的资产）

| 素材 | 它证明什么 | 实证来源（可点开复核） | 等级 |

## 4. 任务三：UR 的研究方法、分析手段与专业工具

### 4.1 用户侧需求发现（区别于 MR 的"市场是否成立"）

| **情境访谈 / 情境 inquiry**（Contextual Inquiry） | 他真实的工作流与卡点（含等输入） | 观察表 + 现场记录 | 在会议室做就废了；必须在他工位 |

### 4.2 信任与采纳（UR 独占，MR 完全不覆盖）

> 3. **方法与工具**：分用户需求发现、信任与采纳、定性分析编码、可用性与学习曲线、场景与设计、证据治理六类，每类给：用什么方法、为什么用它、**具体工具名**、输出物、**坑在哪**；另列"UR 也不会用的工具"。定性结论必须报**编码者间信度**。

## 8. 本文件的局限（诚实交代）

1. **本文仍是"作业标准 + 首批一手素材"，不是完整调研报告。** 市场数与竞争格局见 MR 版，本文不重复。
2. **抽样偏差三条**（都影响结论方向）：
   - **JD 平台偏置**：可观测样本以大厂/上市公司/猎头代招为主，中小散热件厂几乎不挂牌 → **"Excel 热阻网络"被系统性低估**；
   - **自述幸存者偏差**：能被检索到的工程师自述几乎都来自做培训/自媒体/售前的人（既是知识生产者又是卖方），**纯执行岗样本缺失**；
   - **知乎原站不可达**：所谓"知乎来源"实为技术邻/CSDN 同人转载覆盖。
3. **AI 内容农场污染严重**：tsight.io / kwkr.cn / mwwr.cn / hqwc.cn 等站点产出大量"看起来像工程师自述"的文章（无署名、结构同构、结尾一律导流、跨站近乎逐字相同）。本文已剔除或降级，**但这本身是重要信号**：这类内容围剿的关键词（"热仿真报告怎么写""热阻网络计算器""AI 仿真靠谱吗"）正是真实需求所在——**既说明需求存在，也说明工程师在搜索时极易被误导**。
4. **GB/T 8446.2-2022 正文未逐字核读**：字段清单（测点距 300mm/200±5mm、η≤5%、6m/s、4L/min、k=2）来自第三方解读页转述，**用于决策前应调阅标准原文**。
5. **GB/T 22588-2008 标准名未在官方库检索到**；GB/T 34986 检索不到条目（网传出处已被官方库证伪）；GB/T 9254.1 是 EMC 发射、GB/T 9278 是涂料标准 —— **均非散热标准**，此前分类错误已修正。
6. **未触达任何含签字栏的一手验收表单原件**：找到的《汽车行业研发部工程师热仿真分析报告手册》《汽车座舱热仿真分析报告》均为第三方文库付费/疑似 AI 文档，**不建议采信**。
7. **本文件未做价格与成交验证**：定价区间、竞品真实成交价均未取数。
