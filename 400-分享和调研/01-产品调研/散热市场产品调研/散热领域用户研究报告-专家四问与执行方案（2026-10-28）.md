# 散热领域用户研究报告

**研究视角：产品线／设计中心高级用户研究员。**

本次完成了既有资料审阅、公开一手发布渠道检索、关键主张审查，以及可直接执行的客户研究和验证方案。没有实施客户访谈、付费测试、样件试验或仿真复算，因此文中的商业机会属于有依据的研究判断，不是已验证的产品市场匹配结论。

本报告沿用工作区中的实际项目背景：FEMAI 希望探索企业客户的散热结构优化、仿真和交付机会。上一轮对话使用的手机／笔记本终端热体验范围不作为本报告主线。既有材料中的公司人数、客户数量、技术性能与客户关系仍属内部陈述，本轮没有独立证明。

## 一、先给出可以用于决策的判断

**当前建议：推进一个边界明确、按项目交付的散热设计优化验证，暂不据此立项通用仿真软件或硬件盒产品。**

理由是：公开证据已经显示电子热仿真与几何优化存在成熟供应商；本轮尚没有目标客户的工作流、预算、真实项目、技术回测和采购证据。项目式验证能同时检验问题价值、数据可用性、工程效果和采购路径，但服务需求能否转为软件复购，仍须单独验证。

| 决策         | 本轮建议                            | 证据状态与边界                |
| ---------- | ------------------------------- | ---------------------- |
| 首先研究谁      | 有重复设计任务、可提供历史项目、拥有结构修改权的工程团队    | 研究招募假设；不是已验证的客户画像      |
| 首先研究什么     | 一个结构族中的方案比选、参数优化、报告交接与复核        | 便于控制验证成本；具体结构族由可得项目决定  |
| 首先卖什么      | 有明确输入、交付物和验收范围的工程试点             | 商业路径建议；不能表述为已有付费意愿     |
| 产品如何进入工作流  | 优先复用客户现有 CAD／CAE 工具及报告格式        | 待观察迁移成本与工具接口后确认        |
| 哪些市场暂不主动扩展 | 芯片封装、整机、机房系统等多层级同时进入            | 是资源与验证边界的取舍，不代表没有需求    |
| 硬件盒是否必要    | 暂不确定；只有离线部署、数据控制或许可约束形成采购理由后再评估 | 无软件预算不等于有硬件预算          |
| 市场有多大      | 暂不提供 FEMAI 的可服务市场金额             | 尚无目标客户数量、预算和可实现单价的可靠口径 |

建议的价值主张用于研究，不直接用于销售承诺：

> 在客户现有设计和验证流程内，帮助工程师更快筛选可制造的散热结构方案，并给出可复核的选择依据。

“更快”“可制造”“可复核”分别需要计时记录、工艺审查和独立验证；三者不能互相替代。

## 二、本轮实际查到了什么

### 2.1 证据使用规则

每条主张同时标注三个维度，避免把“来自官网”误当成“客观成立”：

- **来源性质：**原始用户记录／交易记录／实测数据／官方自述／第三方分析。
- **核实状态：**已核验发布内容／内部陈述／研究推断／待采集。
- **独立性：**利益相关／独立来源／独立复现。

厂商官网是一手产品自述，能证明厂商发布了相应功能或许可方式；不能独立证明性能领先、客户实际使用或采购效果。IDC 是研究机构的原始发布渠道，但其市场数字仍是分析结果，不是未经加工的原始交易数据。

### 2.2 已核验的公开发布内容

检索与访问日期均为 **2026-10-28**。标准仅核验了公开介绍，未取得付费标准全文，不据此声明任何项目已符合该标准。

| ID | 本轮查得 | 证据能支持的结论 | 不能支持的结论 |
|---|---|---|---|
| E01 | IDC 于 2026-08-10 发布文章，给出 2025 年中国电子散热仿真软件市场 3.64 亿元 [S1] | IDC 公开发布了该口径的规模估计 | 不是 FEMAI 的 SAM；公开文字不足以确认旧文所称“仅订阅与一次性授权、不含服务”的全部细则 |
| E02 | Simdroid-EC 官方页覆盖芯片、PCB、设备和系统层级，并介绍模型库与文件导入 [S2] | 国内已有面向电子散热工作流的产品供给 | 不证明实际市占率、客户装机、交付效果或 FEMAI 没有机会 |

| E05 | SimScale 官方页列出免费学习／测试方案与定制报价的商业方案，商业方案包含私有项目等配置 [S5] | 可验证公开的套餐结构；不能使用未经核验的旧报价 | 不证明中国目标客户接受云端部署，也不能据其套餐推算成交价 |
| E06 | ASME V&V 20 官方介绍要求针对指定变量和验证点，考虑仿真与实验双方的不确定度 [S6] | 误差指标必须结合实验条件和不确定度解释 | 不支持“过一个算例就全工况可信”或任意通用温差阈值 |
| E07 | CNAS 官方说明要求查看认可证书附件及具体标准／能力范围 [S7] | 可以核查实验室是否具备拟委托项目的认可能力 | 有 CNAS 资质不等于所有项目都在范围内；也不证明商业价值 |

### 2.3 必须纠正的旧判断

| 既有说法或做法 | 问题 | 本报告采用的修正 |
|---|---|---|
| “JD 就是真实工具链”“词频就是工具链份额” | 招聘需求与实际部署、活跃使用存在差距；重复招聘带来偏差 | 只统计“去重样本中的提及率”，再用现场许可证／项目文件核实 |
| “公开未见 AI，所以尚未使用” | 缺少公开披露不构成不存在的证据 | 标记未知，问当前流程、最近项目和采购事实 |
| “k≈0.5 可决定只做塑料、不做金属” | 一个数不能确定材料类别、方向性、工况或系统适配性 | 取得牌号、温度依赖、各向异性、填料和成型信息后判断 |
| “客户软件预算为零，应转硬件盒” | 换一种交付载体并不会自动创造预算或采购理由 | 分别验证需求、预算科目、部署要求与总成本 |
| “假想意愿统一打约 21% 折” | 缺少适用样本与原始依据；不应普遍套用 | 用报价反馈、采购动作、合同与回款分层验证 |
| “翻转率≤10%／MAE≤5℃即可通过” | 没有适用决策、分母、误差后果与置信区间 | 按任务风险、可用裕量和测量不确定度预先约定 |
| “三种市场估计差距小于30%就可信” | 同源假设可能造成虚假的一致 | 检查来源依赖、统计对象和敏感性，而非仅看接近程度 |
| “召回公告就是失效成本” | 公告通常不包含全量损失，原因也未必是热设计 | 只记录已明确披露的原因与金额，缺失成本保持未知 |
| 名单在不同版本出现46家／62家 | 未统一实体、时间和统计范围 | 本轮不复述总数；以原始工作簿去重和确认后再计数 |
| 结构优化／仿真结合“国外或国内空白” | 已有公开产品能力，地域空白也缺系统证据 | 比较具体任务、工艺约束、接入成本与验证成本 |

## 三、任务一：专家会额外做的工作

### 3.1 先重建问题，而不是直接问“需要什么功能”

研究单元是一次真实的设计决策：谁，在什么项目中，为何要改结构，用了什么依据，经过谁批准，最后付出了什么成本。

| 专家额外动作 | 实际执行方式与交付物 | 遗漏的后果 |
|---|---|---|
| 明确要支持的决策 | 将问题限定为进入哪个任务、服务谁、卖什么、什么证据后加投 | 信息丰富，但不能决定投入 |
| 按任务与物理机制切分 | 以结构族、自然／强迫对流、材料、设计阶段和工艺分层 | 混合不同工具和验收要求 |
| 还原完整工作流 | 观察从需求、CAD、边界条件、求解、样件到报告签字的全过程 | 把求解时间误当总周期 |
| 识别使用／采购／验收三条链 | 分别访问工程师、预算负责人、质量或验证人员 | 工程师喜欢，采购或质量不接受 |
| 查实际替代方案 | 比较现有软件、经验公式、外包、供应商配套支持、增加余量和暂不行动 | 漏掉真正让客户不购买的原因 |
| 收集拒绝与失败案例 | 纳入未购买、买后闲置、优化后未采用和失效回退项目 | 只得到熟人和成功案例偏差 |
| 审计数据可得性 | 检查授权、格式、缺失、版本、保密和结果标签 | 以为有数据，实际无法训练或验证 |
| 检验工艺与维护约束 | 把壁厚、脱模、加工、装配、表面处理及维护写进任务要求 | 得到算得好但造不出或用不了的方案 |
| 建立真实经济账 | 从项目记录分离人工、样件、测试、许可证、延期与返工成本 | 把节省的机器时间全部当现金收益 |
| 预先写下反证 | 每条假设关联观察窗口、缺证状态和推翻后的动作 | 任何结果都被解释为支持立项 |
| 评估交付可重复性 | 记录每客户专属配置、手工修复和数据准备工时 | 定制服务被误判成可扩展软件 |
| 审查利益与证据独立性 | 标注合作客户、厂商案例、内部模型和外部实验 | 自研模型与自研标签互相比对形成自证循环 |

### 3.2 初步任务地图与明确取舍

| 任务层级 | 关键工作与风险 | 本轮取舍 |
|---|---|---|
| 芯片／封装 | 结温、封装细节、电热耦合、模型库与测试关联 | 不作为首次切入任务 |
| 板卡／模块 | 布局、器件模型、风道、板级边界条件 | 作为相邻任务观察，不同时承诺产品化 |
| 整机／机柜 | 风扇、系统阻力、噪声、部署与多部件耦合 | 不作为首个完整替代目标 |
| 数据中心系统 | 气流组织、冷却系统、设施运营 | 独立市场，本轮不外推 |
| 有限结构族的设计优化 | 参数修改、制造约束、方案排名、复核与报告 | 首选研究切口；是否进入由真实项目决定 |

“结构件”跨越上述层级，并不是与芯片、板卡并列且互斥的市场口径。不能把各层级加总当作总市场。

## 四、任务二：专家实际需要的原始一手素材

### 4.1 素材清单、获取位置与证据边界

以下客户侧素材本轮均未获得。清单已经定义到可索取和登记的程度，不以模板数量冒充采集数量。

| 原始素材 | 谁／哪里提供 | 必须保留的字段 | 能证明什么／不能证明什么 |
|---|---|---|---|
| 访谈原始录音、现场笔记 | 工程师、采购、质量，各自授权 | 角色、项目、时间、上下文、原话 | 当事人陈述；不自动证明客观因果 |
| 现场屏幕与操作记录 | 工程师实际工作站 | 工具版本、起止、操作、等待、回退 | 工作步骤和耗时；单次不代表全年 |
| 需求单与设计变更单 | 项目管理、研发 | 需求版本、变更原因、批准链 | 实际需求与决策过程 |
| CAD及历史版本差异 | 结构／热设计人员 | 几何版本、参数、单位、修改人 | 输入与结构变化；不证明制造可行 |
| 材料与BOM原表 | 材料、采购、工艺 | 牌号、批次、方向性、物性来源 | 选材与成本输入；手册值未必等于实物 |
| 求解工程和日志 | CAE人员 | 网格、边界、残差、守恒、软件版本 | 数值过程与复现条件；不是物理真值 |
| 试验原始时间序列 | 客户或独立实验室 | 温度、功率、流量、压差、环境、时钟 | 指定条件下的物理响应 |
| 测点与仪器原始记录 | 试验人员 | 布点图、接触方法、校准、发射率 | 测量方法与不确定度追溯 |
| 风扇／泵／TIM数据 | 供应商、测试人员 | 曲线、批次、工况、装配压力 | 边界与接口条件；不能脱离系统套用 |
| DFM、试模与尺寸记录 | 工艺、制造、供应商 | 壁厚、拔模、缺陷、装配、返工 | 制造约束与实际结果 |
| 报价、订单、发票、回款 | 采购与财务，脱敏授权 | 项目、金额、税口径、范围、付款条件 | 实际商业动作；不证明可规模复制 |
| 验收原表与签字记录 | 质量、项目负责人 | 指标、偏差处理、版本、签字身份 | 客户接受依据；不等于独立技术认证 |
| 8D／FA／返工记录 | 质量与售后 | 现象、根因证据、纠正措施、损失凭证 | 特定问题与后果；不能直接推算行业比例 |
| 许可证与真实项目清单 | 工具管理员、工程团队 | 产品、版本、许可方式、实际调用 | 实际使用；招聘JD只能作为线索 |
| 数据划分与模型版本 | 我方技术团队 | 项目族、训练／验证／测试归属、冻结日期 | 排查泄漏；不能代替第三方实测 |
| 预测区间与失败样本 | 我方技术团队 | 分工况覆盖率、区间宽度、越界状态 | 指定测试分布中的不确定性表现 |

### 4.2 公开材料的正确位置

- 官方文档、许可条款、招标原文和公告：是相应发布或采购事项的一手来源；厂商能力仍须标注“自述”。
- 年报研发费用：属于经汇总的披露信息，不是散热任务的原始成本台账。
- 原始JD：能证明招聘要求，不能证明许可证数量或真实装机。
- 论文正文：是研究团队的原始研究报告，但其表格通常已经加工；复核还需要方法、原始数据和代码。
- IDC及券商报告：属于市场分析材料；不能因为来自原发布方，就称作未加工的原始素材。
- 内部旧文档、客户画像、清洗后的名单与AI摘要：作为线索和假设，不作为独立证明。

### 4.3 数据登记规则

每个文件登记：`evidence_id / project_id / owner_role / source / captured_at / version / permission / anonymization / file_path / hash / claim_id / limitations`。

原件只读保留；清洗、编码和统计在副本完成。授权不足时允许现场观察和脱敏摘要，但明确标注其可复核程度下降。缺字段用“缺失／未知”，不补猜测值。

## 五、任务三：研究方法、分析手段与工具

### 5.1 定性研究：把工作、损失和决策链还原出来

**探索样本方案：招募8家组织，每家尽量覆盖工程与采购／验收角色，目标12—16人。** 这是执行配额，不是统计代表性声明。最终样本按实际招募报告。

组织配额建议：2家有成熟CAE团队、2家主要依赖外包或供应商、2家重复任务多但资源有限、2家采购后闲置或评估后拒绝。允许交叉归类，统计时按组织去重；尽量包含无合作关系的组织。优先控制设计任务的可比性，不同时混入所有散热行业。

| 方法 | 操作 | 输出 | 专业工具 |
|---|---|---|---|
| 关键事件访谈 | 只追问最近一次真实项目及证据 | 事件链、损失和决策依据 | 录音、逐字稿、编码表 |
| 情境观察 | 看工程师实际完成一段任务 | 活动／等待／返工分解 | 授权录屏、操作计时 |
| 工件引导访谈 | 用图纸、报告、报价或失效件追问 | 陈述与工件的对应关系 | CAD只读查看器、PDF批注 |
| 组织决策链研究 | 分别询问使用者、采购者、验收者 | 服务蓝图、采购和签字链 | 表格、流程图 |
| 负面案例分析 | 专门收集拒绝、闲置、失败和回退 | 机会边界与替代解释 | NVivo／MAXQDA或表格 |

不以“访谈几人后达到饱和”自动结束。每轮检查：主要任务是否出现新步骤、反例是否被解释、不同角色是否矛盾；未覆盖的关键类型单列限制。

### 5.2 可直接使用的12问访谈提纲

1. 请打开最近一个需要改散热结构的项目，最初触发原因是什么？
2. 上一次具体改了什么，谁提出，谁能批准？
3. 从需求到签字，请按实际顺序展示用过的文件和工具。
4. 哪一步耗费了主动操作、机器等待、排队和返工？分别有何记录？
5. 哪些边界条件最难确定，最后用什么替代或估计？
6. 最近一次算得对但没采用的方案是什么，谁否掉，为什么？
7. 不用新工具时，现有做法是什么，费用由谁承担？
8. 最近一次为软件、外包或测试付费是什么项目，采购走哪条路径？
9. 谁会核验结果，必须看到哪些材料才能签字？
10. 哪些数据能提供、哪些不能，现有保密与部署限制是什么？
11. 若做一个范围固定的历史项目回测，谁能提供输入、谁保管结果？
12. 如果回测通过，下一项真实采购动作是什么，由谁在什么窗口完成？

避免先介绍AI方案再问“想不想要”。价格问题在任务、替代品和现有支出厘清后提出。记录“没发生／不知道／不能提供”，不诱导肯定答案。

### 5.4 技术验证：验证客户的决策，不只验证温度场图像

工具按用途选用：客户现有 Flotherm／Icepak／其他CAE用于工程基线；Python／R做统计与复现；参数化CAD、DOE和优化器用于方案搜索；热电偶、采集器、热像仪、功率计及相应流量／压差仪器用于物理测量。仅列工具不代表本轮已运行或取得许可。

**主指标由任务决定。**

| 决策 | 优先指标 | 必须附带的限制 |
|---|---|---|
| 判断是否超温 | 危险误判率：实际不合格却预测合格的数量／实际不合格数量 | 无不合格样本时不能估计该率 |
| 挑选最佳方案 | 选型后悔值：所选方案真实损失减去候选中的最小真实损失 | 各方案须使用可比验证条件；制造与成本约束同样有效 |
| 初筛候选 | 合格候选召回与筛除比例 | 不能仅追求多筛除，漏掉合格方案也有成本 |
| 改善热性能 | 热点温差、热阻、压降等指定验证量 | 按材料、热源、边界和工况分层 |
| 节省设计周期 | 从合格输入到可签字输出的总时间与人工时间 | 包括数据准备、复核、失败重跑和报告 |
| 跨项目复用 | 新项目手工配置与修复工时、失败比例 | 不用单客户熟练操作替代跨客户验证 |

L2温度场误差仅作诊断：整体误差低仍可能掩盖热点或临界点；绝对温标、场域与归一化方式也会影响解释。不能只报一个平均值。报告中给出项目数、工况数、结构族、误差分布、置信区间和失败样本。

**不得设无任务背景的统一“5℃合格线”。** 先确定设计上限、可用温度裕量、实验不确定度和失误后果，再约定预测与决策容限。一个工况的符合不外推为全工况可信。ASME官方范围说明支持这种指定变量和验证点的评估方式。[S6]

### 5.5 第一个可信实验：冻结结果的历史项目回测

以下为拟执行协议，不是已完成实验。

1. **准入：**争取3个独立客户项目，来自一个明确结构族。每项目至少保留一个设计输入、一个已完成参考结果及完整边界条件。项目不足时报告为单案例可行性。
2. **冻结：**由客户或独立保管人封存结果；我方只拿到允许的输入。冻结模型版本、代码、输入清单、指标、容限和排除规则。
3. **比较：**至少比较客户原流程、现成CAE／已有参数化优化流程、我方方法。条件可比且资源可得时增加经验热阻模型、DOE、代理模型等；不为凑数量使用不适用基线。
4. **分离样本：**按项目或几何族划分数据，禁止同一项目相邻工况随机拆进训练和测试后宣称跨项目能力。检验域外输入能否识别并回退。
5. **计时与计费：**记录首次准备、训练、推理、求解、复核、失败处理和报告；同时报告冷启动与重复任务，计算硬件和许可保持可追溯。
6. **解盲：**保管人开启结果，独立人员按冻结规则计算指标，记录所有失败和缺失。预测区间同时报告覆盖率与宽度。
7. **物理闭环：**历史结果若仅来自CAE，只能验证与该基线的一致性。要声明改善实际热性能，须追加样件和独立测量，并检查数值与实验不确定度。
8. **结论：**3项目仅支持探索性跨项目可行性。不能据此声称低危险误判率、行业通用精度或规模化收益。

算力与费用不编固定值。先用一个代表算例试跑，按“数据生成＋训练＋全部基线＋复核＋预计失败重跑”估算资源；把许可证、CPU/GPU规格和计费方式附在实验卡，再确定完整实验预算。

## 六、任务四：独立于你我之外的验证依据与渠道

### 6.1 四种有效性分别验证

| 有效性 | 核验人／渠道 | 所需证据 | 核验边界 |
|---|---|---|---|
| 事实有效性 | 原发布机构、独立资料审阅者 | 原文、页码、时间、统计定义 | 发布确实存在不等于主张已被独立验证 |
| 物理有效性 | 无我方开发责任的工程人员、具备适用能力的实验室 | 样件、原始数据、校准、边界、网格与不确定度 | 只针对约定变量、工况与结构族 |
| 使用有效性 | 独立招募的真实工程师，使用新任务 | 成功率、误设、返工、主动时间、信任校准 | 解释研究样本与组织范围 |
| 商业有效性 | 客户采购／财务、合同及回款记录 | 可核对的交易范围、价格、直接交付成本 | 单个付费项目不证明软件复购与市场规模 |

客户技术签字是采用证据；合作客户仍有利益关系，不算完全独立。可让独立实验室做物理验证、非项目成员做盲评、陌生客户做任务复测。保留不一致结果，不以多数票替代技术审查。

| 假设 | 观察窗口与证据 | 支持继续的门槛 | 不支持／缺证后的动作 |

补充反证路径：现有CAE自动化若已同样有效，差异化不成立；供应商配套服务若足够且难以替代，转向其他任务；客户若只需要外包能力，不推导其愿意订阅；独立物理测试若推翻基线，先审查基线而非调模型追数；若陌生客户无法复现，收缩到已验证结构族。

## 七、市场与竞品结论：先有边界，再谈机会

### 7.1 已有供给，不应以“没有工具”作为立项理由

公开产品页已经显示：Simdroid-EC覆盖电子热分析工作流，nTop展示复杂换热几何与CHT结合，SimScale提供云仿真套餐。[S2–S5] 这些属于供给存在的证据，尚不是对适配性与性能优劣的横向评测。

更值得验证的差异化位置是：针对特定工艺和结构族，减少输入整理与试错，保留现有工具链，输出可制造且能复核的候选。该机会仍可能被现有CAE脚本、工程外包或供应商服务覆盖。

### 7.2 不把相邻市场规模当收入空间

IDC的3.64亿元是特定年份、中国电子散热仿真软件市场的公开估计。[S1] 它不能直接代表结构优化服务、全部散热研发支出或FEMAI可取得的收入。本轮不引用未回到原表核对的厂商份额。

后续自下而上估算采用：

`可服务支出 = Σ（符合任务条件的独立预算单元数 × 可核验的同口径年采购支出）`

`近期收入能力 = 可交付项目数 × 经采购反馈验证的项目价格`

`可交付项目数受限于 = 可用交付人天 ÷ 包含返工和支持的单项目人天`

分别报告低／中／高情景及每个输入的来源，不把可节省成本全部当作可捕获收入，不把研发费用总额等同散热软件预算。

## 九、优化后的原始问题

> 请以产品线／设计中心高级用户研究员的身份，研究FEMAI面向企业客户的散热结构设计、仿真与优化机会。先读取已有项目资料，明确目标用户、设计任务、工艺、购买与验收角色及决策范围；缺失背景显式标注，不以消费终端体验替代企业研发工作流。
>
> 按顺序完成四项任务：
>
> 1. 说明顶尖专家会额外开展的工作，每项给出目的、执行动作、交付物、遗漏风险；覆盖任务分层、工作流观察、替代方案、失败样本、采购链、工艺约束、交付经济与反证，并给出本轮明确取舍。
> 2. 列出需要的原始用户、组织、交易、设计和实测素材，给出获取对象、字段、授权、质量控制、能证明与不能证明什么；区分原始记录、厂商自述、研究报告和内部推断，标记本轮实际获得与尚缺材料。
> 3. 将研究问题映射到样本策略、具体方法、分析指标和专业工具，产出访谈提纲、观察记录、工作流成本表、采购证据漏斗和冻结回测协议。技术比较包含现有流程与适用基线，检验热点、选型风险、制造约束和全流程收益，避免仅凭平均误差或求解加速判断价值。
> 4. 分别为事实、物理、使用和商业结论定义独立核验渠道，列出原始证据、复现要求、不确定度、通过与否证条件及适用范围。说明客户签字、厂商宣传、独立实验室和真实交易各自能证明什么。
>
> 最后给出证据追溯表、已有判断与待验证假设、可执行排期、产品／服务进入或停止条件，并改写本问题。先完成公开证据可支持的工作；未执行的访谈、测试和采购验证不得写为已完成，不用缺乏来源的市场数字、价格、阈值或客户比例填补空白。
