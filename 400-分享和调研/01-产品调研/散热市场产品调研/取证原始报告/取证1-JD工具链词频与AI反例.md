## 抽取方法与局限

**方法**
1. 用 9 组中文检索词定位候选 JD（热设计/热仿真/散热工程师 × Ansys Icepak / Flotherm / 6SigmaET / 车灯 / 冷板 / 散热模组 / TestLab / 热阻网络 / Excel / Python 脚本 / AI 代理模型 / 车灯企业官网等），共获得 60+ 条候选 URL。
2. 对每条候选执行 WebFetch，逐条落地"岗位名｜公司｜城市｜职责原文｜要求原文｜软件词"六元组。
3. 软件词按大小写与变体归并（IcePak↔Icepak；FloTHERM↔FLOTHERM↔FLOTHERMXT；Ansys Mechanical 单列并计入 Ansys 系）。
4. 频次统计以"JD 正文实际出现该词"为一次命中，**同一 JD 内重复出现不重复计数**。

**局限（必须写明）**
1. **JD 反映的是招聘需求，不是采购事实。** 一条 JD 要求 Flotherm，只说明该岗位候选人应当会 Flotherm；它**不能证明**该公司已采购 Flotherm、不能证明 license数量、不能证明没有用 Excel/手工拓扑做初筛，也不能证明实际工作流就是跑 CFD。**采购决策权、预算归属、实际工具使用强度都不可从 JD 推断。**
2. **样本有强平台偏置。** 猎聘/智联/51job 覆盖的以大厂、上市公司、猎头代招岗为主；中小散热件厂（真正用 Excel 热阻网络的群体）在这些平台上几乎没有挂牌 JD，因此**"Excel 热阻网络"很可能被系统性低估**。本报告因此**不能证否**"客户主要靠 Excel"，只能说"**在可观测的招聘 JD 中，Excel/脚本化几乎不作为准入条件**"。
3. **岗位层级分布偏中高端。** 已核验样本以"热仿真专家/热设计主管"级为主（20–80k 区间多），初级/结构工程师岗（10–20k）样本少，导致软件要求看起来比一线实际作业更重。
4. **AI 相关样本严重不足（3/39）。** 且3 条中有 2 条来自 CAE 软件厂商与研究型单位（#38 中久数创、#39 合肥水泥），只有 1 条来自甲方（#34 宁德时代一维速算模型）。**"散热行业已引入 AI/代理模型"这一命题在本样本中仅在极少数岗位成立，不具行业代表性。**
5. **51job 三条关键样本（领灿、道格特、恒翼能）均已下线**，其中道格特那条是唯一明确写"建立整屏热阻网络模型"的甲方证据——**这个关键反证恰好也是验证最弱的一条**，需在正式报告中显著标注其不确定性。
6. **热度极低但目标极高的词**：Siemens / Cadence / Altair / nTop / SimScale / Inspire / **TestLab** 在 39 条已核验 JD 中出现 **0 次**。这不能证明中国市场不用这些工具（尤其是 TestLab，制造业渗透率可能远高于招聘可见度），只能说明**招聘 JD 不是这些工具的观测窗口**。

**对清航飞迈的直接可用推论（供内部判断，非结论）**
- 招聘 JD 显示：**几乎所有甲方岗位的硬门槛是"CFD 三维仿真 + 实测对标"**，而"脚本化/降阶模型/一维速算"只有 7/39（18%）出现，且集中在宁德时代、比亚迪这类大厂与 CAE 厂商。
- 这与假设"客户主要靠 Excel 热阻网络 + 手工拓扑 + 台架实测 + 偶发 CFD"**并不矛盾**：JD 只公开"终态能力要求"，而 Excel 热阻网络这种**工作流起点**在 JD 中天然不可见（没人会在 JD 里写"请熟练使用 Excel 建热阻网络"，就像没人在 CAD 岗里写"会用记事本算坐标"）。
- **因此，这批 JD 证据更适合用来论证"降阶/代理模型在中国散热行业尚未成为招聘硬需求（≈18%，且非甲方主体）"，而不能用来论证"客户已经在用 Excel 热阻网络"。** 后者需要另外的取证路径（供应商访谈、招标公告、企业官网技术白皮书、CAD/CAE插件市场数据）。
