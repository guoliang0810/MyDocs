# 面试题库与应答

> **本库的原则：每道题都给出"面试官在考什么"和"答题结构"，不给万能话术。**
> 话术是死的，问题契约是活的。

---

## 零、⭐ 三条面试通则

| # | 通则 | 说明 |
|---|---|---|
| 1 | **先讲结论，再讲过程，最后讲边界** | 电话面尤其重要——对方只能听声音。结构化是唯一保险 |
| 2 | **每答完一段，主动停在"边界"上** | 说"这块我负责到 __，后面的 __ 是 ___ 团队做的"。**主动交边界比被追问出来强十倍** |
| 3 | **不确定就说不确定，但要说清怎么确认** | "这个我记不准了，准确数字我回去查了发您"——比编一个安全。⚠️ 但**已核实的数字要敢给** |

> ⭐ **面试官真正在验证的三件事**（不只是能力）：
> ① 你的能力**是否真实** ② 是否**可迁移** ③ 解决问题的方法论**是否成熟**
> ——所以每个案例都要能扛住"追问路径"：
> **客户需求 → 产品能力 gap → 方案调整 → 交付效果**

## 一、⭐ FDE / 解决方案架构师 高频题

### 1.1 技术深挖轮

#### Q1. 讲一个你深度参与的售前/交付项目。（必考）

**考察**：真实性、深度、结构化表达能力。

**答题结构（STAR-L 变体，L = Learning/边界）**：

```
① 场景定位（30 秒）
   客户是谁、什么行业、项目处在哪个阶段（PoC / 已上线 / 续约）
   一句话说清项目在客户整体战略里的位置

② 客户原话（⭐ 关键）
   直接引用客户的原始表述——"客户说：'我们要轻一点'"
   → 然后立刻做"问题契约"四要素拆解

③ 我的具体动作（主体，60% 篇幅在这）
   - 拆成目标量 / 方向 / 约束 / 验收判据
   - 建约束台账
   - 声明参数空间（优化空间 ≠ 允许空间）
   - PoC 阶段就暴露简化假设清单 + 影响量级

④ 结果与边界
   - 结果：用可核验的数字（口径要能说清）
   - 边界：⭐ "我负责的是 __；标书撰写 / 合同回款是 ___ 团队负责的"

⑤ 复盘（一句）
   "如果重做，我会把 ___ 提前到 ___ 阶段"
```

> ⭐⭐ **第 ② 步"引用客户原话"是拉开差距的地方。**
> 多数候选人讲项目从技术开始；顶尖的人从**客户那句话**开始。
> 因为 FDE 的第一个动作就是翻译，而翻译的前提是你真的听见了客户在说什么。

#### Q2. 客户需求很模糊，你怎么开始？

**标准答法（用问题契约）**：

```
目标量 / 方向 / 约束 / 验收判据  ← 四要素
```
再补三个动作：
1. **先问"轻一点"具体是多少**——把形容词变成数字
2. **画失败路径**：这个做不成怎么办？降级方案是什么？
3. **明确不做什么**：PoC 阶段就声明排除的区域

> ⚠️ **淘汰标志**：听完需求直接讲技术方案，中间没有追问、没有诊断框架。

#### Q3. 客户说"你们太贵了，友商便宜一半"。（售前高频）

**四段式**：
1. **共情**：理解客户的预算压力是真实的，不是抬杠
2. **拆价差**：友商的报价里**不含**什么？（实施、数据迁移、培训、年度支持、后续定制）
3. **换算**：把价格差换算成**风险敞口**——"省下的 __ 万，如果 __ 个月后仿真结果对不上试验，您要付出的是 __"
4. **给方案**：不是降价，是**换范围**——先做最痛的 __ 场景，验证后扩展

> ⚠️ **绝对不能**：立刻降价 / 贬低友商 / 说"我们技术更好"。

#### Q4. 客户要求的功能超出产品能力边界，且产品团队支撑不理想，怎么办？

**结构**：
1. **不硬顶也不硬接**——先判断这是"真需求"还是"假需求"
2. **给替代路径**：现有能力 + 配置 + 二开的组合解，明确二开的成本与周期
3. **沉淀机制**：⭐ 这是 FDE 的关键动作——**把这个需求写进产品需求文档并排序**，而不是只在客户侧 hack
4. **设定退出条件**：如果客户不接受替代方案，就明确这单不适合做

> ⭐ 面试官想听的是第 3 点。**能落地又能把需求回流产品的，才是 FDE；只会 hack 的是外包。**

#### Q5. 你的方案怎么让客户"敢签字"？

**这是本岗位最核心的一题，也是我的强项题**。答法：

```
① 拆开三种"签字"的含义：
   - 方案比选（选型签字）—— 门槛：趋势合理 + 覆盖关键工况
   - 设计放行（工程签字）—— 门槛：GCI ≤ 5% + 与试验对标在约定带内
   - 适航/临床符合性证据 —— 门槛：合规审查 + 全套可追溯归档
   ⭐ 三者法律与工程含义完全不同，不能混着说

② 交付"结果血缘包"：
   求解器版本与编译选项 / 网格 / 输入卡 / 材料卡 / 边界条件 / 求解日志 /
   GCI 研究 / 迭代收敛历史 / 随机种子或模型权重 hash / 后处理脚本
   —— 没有元数据的结论无法支撑高后果决策

③ 把"不能"做成合法交付物：
   ⭐ 在航空/医疗场景，一个基于不可信模型的减重承诺直接导致适航或临床风险。
   把不可行性证成（带 GCI 数字），比给一个乐观的减重数字更有价值。
```

> ⭐⭐ 这一题如果答得好，**几乎可以单独拿下 FDE 岗**——因为它证明我懂"可信度"这个行业核心矛盾。

#### Q6. 讲一次你在客户现场没搞定的经历。

**考法**：抗压 + 诚实 + 复盘能力。

**结构**：
1. 现象（客观，不带情绪）
2. 我当时怎么判断的（为什么当时那个判断是对的，**在当时信息条件下**）
3. 后来证明我错在哪（如果确实错了）
4. ⭐ **但要区分两种结论**：
   - "决策当时合理，信息不足" → 这是**专业判断**
   - "我该早点升级/该早点止损但没有" → 这是**流程改进**
   ⭐ **只有第二种才是真正的成长**，面试官要听的是这个

### 1.2 沟通与抗压轮

#### Q7. 客户不信任你，你的项目要延期了，Sponsor 在会上发火。

**四步**：
1. **先接情绪，不辩解**——"我理解，这个等待对您的团队是真实成本"
2. **给事实，不给承诺**——当前状态：哪些已完成、卡在哪、需要什么
3. **给选项，不给唯一方案**——A 降范围保时间 / B 保范围延时间 / C 拆阶段先交关键结果
4. **落到纸面**——当场定下一步、责任人、时间点，下次会议怎么验收

> ⚠️ **淘汰标志**：只会说"我们会加班赶出来"。

#### Q8. 你的技术方案，客户老板听不懂怎么办？

**方法**：
- **换语言**：从"网格无关性"换成"同一台机器上换三种精度算三遍，数字稳不稳"
- **换主体**：从"我们实现了 XXX"换成"贵司的 ___ 部门在 ___ 上省了 ___"
- **换证据**：给一个可摸的东西——一页纸 + 一个图 + 一个可核验的数字
- ⭐ **用行业里的信任机制说话**：
  - 军工：编—校—审批三级 + 所级评审 + 同步归档
  - 商业：CAE 工程师签字 + 网格无关性 + 试验对标
  - 医疗：不签字，改为术中术后验证

## 二、⭐ 大客户销售 / 技术销售 高频题

#### Q1. 你从 0 做过一个市场吗？

**⭐ 这是我的杀手题，必须用六步闭环答**：

```
① 需求：企业端真实要什么人（从企业真实需求反推，不是从课程表出发）
② 产品：定课纲 / 定制内容
③ 渠道：怎么招到人（地推、宣讲、渠道合作）
④ 交付：教会
⑤ 结果：学员就业（我负责的结果）
⑥ 反馈：复盘迭代，再扩张

⭐ 迁移说明：
"这六步与做工业软件大客户的逻辑完全同构，标的从课程换成软件。
尤其是第 ① 步和第 ⑤ 步——工业软件销售难的不是讲方案，是**从 0 找到对的人并让他签**。"
```

#### Q2. 你的销售业绩是多少？

> ⚠️ **本题是硬伤区，必须用"诚实 + 迁移"处理。**

**答法**：
```
"我没有独立签单业绩，我这三年的角色是产品负责人 + 前置交付——
我把客户从'想试试'推到'签字验收'，签的是技术验收和预算立项，
但最终合同是销售签的。

我不打算假装有。但我想说的是：
这个岗位最难的是'从 0 让一个陌生客户愿意第一次试'，
我在培训学校做的第一年就是这个——从 0 到有第一批学员。

所以我更适合从**售前 / 技术销售**切进去，用 6–12 个月建立行业客户关系，
再往大客户销售走。如果贵司的岗位是纯资源型、需要马上带客户过来的，
我可能确实不匹配；如果是从 0 开拓型，我能干。"
```

> ⭐⭐ **这个答法的价值**：它同时做到了三件事——
> ① 不造假 ② 把劣势转成路径 ③ **主动帮面试官做筛选**（这会加分，因为诚实候选人显得可信）

#### Q3. 你的提成方案怎么算？如果这季度没完成呢？

**必须问清的问题清单**（面试时反问，答得好加分）：
- 试用期底薪多少？考核缺口是否补差？
- 提成起算点是**签单**还是**回款**？回款周期多长？
- 保护期多长？保护期内离职怎么算？
- 新客户 vs 老客户续约的提成是否一样？
- 资源支持：线索谁给？展会谁去？技术方案谁出？

> ⭐ **反问本身就是评分项**——它证明你知道这行的钱是怎么赚的。

#### Q4. 客户说"我再考虑一下"，你怎么办？

**别答"等他回复"**。答：
1. 拆解"考虑一下"到底在考虑什么——**预算？决策人？技术疑虑？还是没人推**？
2. 找出真正的**决策人**，以及**谁在反对**（往往不是客户，是内部的某个角色）
3. 针对真实障碍给一个可执行的下一个动作（不是"再聊聊"，是"我安排一次 XX 对话"）
4. 设一个明确的复访节点

#### Q5. 我们给你 3 个月做出 XX 万，你怎么做？

**答"先做可复制的漏斗，不做一锤子买卖"**：
```
第 1 个月：客户地图 —— 目标行业里前 ___ 家，按决策链分层（老板/研发/工艺/IT/采购）
             从我已有的行业理解里挑出最可能先动的 ___ 家
第 2 个月：样板 —— 挑 1 家做深，把方案做成可复用的行业方案（而不是一次性定制）
第 3 个月：复制 —— 用同一个行业方案打第 2、第 3 家，把交付成本打下来
```
> ⭐ 这个答法证明"我懂 LTV 和复制"，不只是"我能跑客户"。

## 三、⭐ 通用高压题

| 题 | 答法要点 |
|---|---|
| **你的职业规划？** | 3 年内：成为物理 AI 工业软件领域能独立带大客户交付的架构师，沉淀行业方案资产；5 年内：要么在一家把 FDE 做成真 FDE 的公司里做到交付负责人，要么具备带一个行业线的完整能力。别答"想创业"（除非真要） |
| **期望薪资？** | ⭐ **先问范围**："这个岗位的薪资带宽是多少？"再给区间。FDE 岗可给 40–60 万（大厂 AI FDE 88–109 万是另一赛道，别乱报）；工业软件售前可给 30–45 万；大客户销售**先看底薪结构再谈** |
| **为什么离开我们公司？** | 不评价现公司。讲"我在当前岗位上 ___ 已经做完了，我想要的下一个是 ___" |
| **你怎么看待加班？** | 交付岗位确实有峰值。但请说清：我们的峰值是"版本发布前"还是"客户验收前"？是否轮值？——**把加班问题变成对工作模式的了解** |
| **你最大的缺点？** | ⭐ 选一个**真实但可控、且正在被管理**的短板，并给出管理动作。不要选"我太追求完美"这种假短板 |

## 四、⭐ STAR 案例库（4 个，够用且都真）

| 案例 | 面试官听到什么 | 可支撑的岗位 |
|---|---|---|
| **C919 复材机翼仿真** | 大工业项目、需求工程化、可信度意识、边界感 | FDE 架构师 / 售前 |
| **21 天智能体工程课程包** | 表达与教学、体系化、从 0 造内容资产 | FDE 架构师 / 大客户销售 |
| **郑州培训学校 0→1** | 市场冷启动、从 0 到 1、担结果 | 大客户销售 |
| **车载感知评测 Pipeline** | 技术验证能力、自动化、数据驱动 | 售前 / 技术销售 |

> ⭐ **每个案例都要准备 3 个版本**：30 秒（自我介绍用）、3 分钟（标准轮）、10 分钟（深挖轮）。
> **深挖轮的追问必须提前自己走过一遍**——否则会在第三层追问崩掉。

## 五、⭐ 面试前 24 小时清单

```
[ ] 简历与本档事实完全一致（尤其时间线）
[ ] 社保自查已完成，无未解释的重叠/空窗
[ ] 前主管已告知
[ ] 目标公司最近 3 条产品动态/新闻已看过，能说出它现在卡在哪
[ ] 目标公司 JD 的每一条硬要求，已能对应我的一个具体证据或一个诚实的"我需要补"
[ ] 4 个 STAR 案例的深挖版已过一遍
[ ] 反问清单已准备（5 个问题）
[ ] 薪资区间已定，且基于对方带宽而非期望
[ ] 竞业条款状态已确认
[ ] 着装/设备/网络/备份摄像头已就位（线上）
```
