# 求职作战计划

> ⭐ **排序逻辑：按"能否通过面试"排，不按"学习难度"排。**
> 先解卡简历的（一票否决），再解卡面试的，最后才是提升上限的。

---

## 零、⭐ 90 天总览

| 阶段 | 主线 | 唯一目标 | 判定标准 |
|---|---|---|---|
| **D1–D14** | **事实澄清 + 简历定稿** | 把 5 项硬冲突解决，简历能投 | [[50-风险与合规/简历风险处置清单]] 签署清单全部打勾 |
| **D15–D45** | **岗位研究 + 定制投递** | 建立目标公司清单 + 每周 10 家定制化投递 | 简历通过率 ≥ 40% |
| **D46–D75** | **面试主场 + 证据补强** | 至少 2 家终面 | 至少 2 次进入终面 |
| **D76–D90** | **终局：拿 offer 或调整路径** | 决策 | 拿到 offer，或拿到明确的"方向被证伪"结论 |

> ⭐⭐ **全程并行的一件事（不能等）**：
> **从 D1 开始，按月采集现职业绩数字。**
> 因为这些数字是简历里最有说服力的部分，而它**只会在职时产生**——
> 离职后就永远拿不到了。
> 拖延的代价是：**简历里永远只能写"负责"不能写"做到了"**。

## 一、D1–D14：事实澄清与简历定稿（最高优先级）

> ⭐ **这一阶段不做任何"能力补课"。** 因为补课的成果无法通过一份有硬伤的简历。

| # | 动作 | 产出 | 卡点 |
|---|---|---|---|
| 1 | **查社保记录** | 全部参保单位与月份清单 | 无（唯一由你完全掌控） |
| 2 | 确认 ① 车载感知段雇主主体 | 结论 + 证据（合同/离职证明） | 需查合同或问前 HR |
| 3 | 确认 ② 入学年份 + 年龄栏 | 与毕业证一致 | 查毕业证 |
| 4 | **删除"字节跳动综合服务平台"项目** | 所有版本已清理 | 无（今天就能做） |
| 5 | 确认 ④ 清航飞迈时间线（合并 or 分列） | 结论 | 查劳动合同 |
| 6 | 核实英语水平 | 有证 → 写；无证 → 不写 | 查成绩单 |
| 7 | 查现公司竞业条款 | 结论 | 查合同/手册 |
| 8 | **建立业绩数字台账**（见第二节） | 可持续更新的表格 | 无 |
| 9 | 定稿两版简历 | PDF × 2 | 依赖 1–7 |

### ⭐ 8 号动作的具体设计（业绩数字台账）

**从本月起，每月 5 号前更新一次。字段如下：**

| 字段 | 记录内容 | 示例（待填） |
|---|---|---|
| 主导 PoC 数 | 我负责定义问题契约 + 验收判据的 PoC | __ 个 |
| PoC 转正率 | 转正 / 交付总数 | __% |
| 一次验收通过率 | 无返工直接过的交付物比例 | __% |
| 典型交付周期 | 从问题契约到验收的天数 | __ 天 |
| GCI 实际水平 | 我交付的方案里网格无关性做到多少 | ≤ __% |
| 与试验对标偏差 | 目标输出量相对试验的偏差带 | ≤ __% |
| 回流资产数 | L1 模板 / L2 参数库 / L3 插件 / L4 API 各几项 | __ / __ / __ / __ |
| 复用次数 | 回流资产被其他客户复用几次 | __ 次 |
| 客户数量 | 深度接触过的客户数（脱敏） | __ 家 |
| 行业覆盖 | 航空航天 / 装备 / 医疗 各 __ 个场景 | |
| 节省的客户时间 | 有对比基准才记，否则不记 | |

> ⭐ **记录纪律**：
> ① **只记能说出口的数**——面试要能解释口径
> ② **没有基准对比的数字不记**（"效率提升了"没有基准 = 0）
> ③ **脱敏**——不记客户敏感信息，只记可公开的量级

## 二、D15–D45：岗位研究与定制投递

### 2.1 目标公司清单（建 60–80 家，分三档）

| 档位 | 数量 | 特征 | 打法 |
|---|---|---|---|
| **A 档 · 主攻** | 15–20 | 物理 AI / CAE / 工业软件厂商，有自研平台（⭐ 满足"真 FDE"四问：自研平台 / 按结果验收 / 工程师去现场 / 有回流机制） | 定制投递 + 内推 + 行业社群直接触达 |
| **B 档 · 主力** | 25–30 | 仿真软件厂商（安世亚太、数巧、开创工软、索辰、适创、仿真秀生态）、超算/CAE 云（并行科技）、国产 CAE 新势力 | 定制投递 |
| **C 档 · 机会** | 20–30 | 头部 CAE 厂商中国区（Ansys / 达索 / Siemens）、AI 大厂 FDE（作为阶段 2 目标）、行业软件龙头 | 批量投 + 观察 |

> ⭐ **渠道优先级（按转化率从高到低）**：
> 1. **内推**（在职员工 / 前同事 / 前主管）—— ⭐ 转化率最高，且能提前化解背调风险
> 2. **行业社群直接触达**（仿真秀、CAE 工程师社区、行业会议）—— 能直接找到人
> 3. **猎聘 / BOSS / 智联**（HR 主动捞）—— 量大但需定制
> 4. **公司官网投递**—— 兜底
>
> ⭐⭐ **不要只刷招聘 App。** FDE / 售前这种岗位，
> **大量是"先有人愿意推荐你"而不是"你先投简历"**。
> 建议同步做：**每周主动联系 3 位目标公司的在职员工**（问岗位真实情况 + 要内推）。

### 2.2 每周固定动作

| 频次 | 动作 | 数量 |
|---|---|---|
| 每天 | 定制化投递 + 更新投递台账 | 2–3 家 |
| 每天 | 在目标公司列表里联系 1 位在职员工 | 1 人 |
| 每周 | 复盘本周被拒/通过的简历差异 | 1 次 |
| 每周 | 更新 1 个话术（STAR 案例的深挖版） | 1 个 |
| 每周 | 补 1 个证据（跑一个 NAFEMS 算例 / 写一份行业方案） | 1 件 |

### 2.3 投递台账字段（学 CRM，别靠脑子）

```
日期 | 公司 | 岗位 | 档位 | 渠道 | 简历版本 | 投递人/内推人 | 
状态（已投/已读/已约面/已面/终面/ Offer/拒）| 
拒信原因（简历/学历/经验/薪资/其他）| 下一步动作 | 下次跟进日期
```

> ⭐ **"拒信原因"这一列是整张表最值钱的**。
> 拒 10 家之后回看分布，就能知道**问题出在简历、经历、还是面试**——
> 这是求职版"从结果指标往前推过程指标"。

## 三、D46–D75：面试主场 + 证据补强

| 优先级 | 补什么 | 怎么做 | 为什么值 |
|---|---|---|---|
| **P0** | ⭐ **CAE 求解器实操 + 一个可信的对标结果** | 亲手跑 NAFEMS 静力 P07 + CFD R0123；用 AICube/Solid 跑自有场景做完整仿真，出一份带 GCI 的报告 | **JD 第一硬门槛**（10 条原文一致）。⭐ **一份带 GCI 的对标报告，比任何证书都有说服力** |
| **P0** | 现职数字台账补齐 | 见第一节 | 简历主句全靠它 |
| **P1** | 仿真可信度 V&V | ASME VVUQ 10/20/40 + GB/T 33582-2017；把 V&V 章节写进交付报告模板 | 售前技术深挖必问 |
| **P1** | 代理模型工程化 | NeU-PINN / FNO 失效模式 / NeuralUQ；十项验证清单落地为默认流程 | Solid 核心能力 |
| **P1** | 招投标/标书 | 参与一次真实投标（配合写技术标） | 售前 JD 明确要求 |
| **P2** | PLM/PDM/SDM | 补基础概念 | 加分项 |
| **P2** | NAFEMS PSE 认证 | 考 | 行业背书 |
| **P2** | 英文技术写作 | 写 1 篇英文案例 | 国际化加分 |

> ⭐⭐ **P0 的第一项为什么排在所有补课之前**：
> 因为它同时解决三个问题——
> ① 补上 JD 第一硬门槛 ② **产出一份可展示的硬证据**（对标报告）
> ③ **同时补齐现职业绩数字台账**（跑算例 = 有 GCI、有交付物、有周期）
>
> ⭐ **而且它有现成资源**：本库 [[100-物理AI产品与领域/020-领域知识/仿真可信度V-V与标准体系]]
> 已经把标准体系梳理好了，缺的只是"亲手跑"。

## 四、D76–D90：终局决策

### 4.1 决策矩阵

| 结果 | 判断 | 动作 |
|---|---|---|
| 拿到 offer（A 档公司，FDE/架构师岗） | ✅ 最优路径 | 谈薪时确认：是否按结果验收、驻场比例、回流机制、团队规模、**有没有客户资源支持** |
| 拿到 offer（纯资源型大客户销售） | ⚠️ 需慎重 | ⭐ 问清底薪、提成起算点、保护期、指标缺口补差。**若必须自带客户资源 → 拒** |
| 拿到 offer（CAE 售前/技术支持） | ✅ 可接受 | 作为进 CAE 赛道的入口；1–2 年后横向转架构师或销售 |
| 拿到 offer（换皮外包"假 FDE"） | ❌ 拒绝 | ⭐ **用四问检验**：有没有自研平台 / 合同是否按结果验收 / 工程师去没去过客户现场 / 有没有回流机制 |
| 无 offer，但有终面 | 🟡 未失败 | 回看拒信原因分布：简历问题 vs 面试问题 vs 岗位错配 |
| 无 offer，无终面 | 🔴 需调整 | ⭐ **大概率是简历被卡**（不是能力问题）。重读 [[50-风险与合规/简历风险处置清单]] 与投数量 |

### 4.2 谈薪的三个锚

| 锚 | 数据 | 用法 |
|---|---|---|
| **市场下限** | 国内 FDE 均值 40.8 万 / 中位 36.6 万；50 万以上占 28.25% | 报区间时用中位数往上 |
| **赛道校准** | CAE 售前/应用工程师：10–30K×13；数巧 15–30K×13；安世亚太 1.8–3 万；并行科技架构师 2.5–4 万×13 | ⭐ **投工业软件赛道，就用这个区间的上沿，别用 AI 大厂的数** |
| **自证价值** | 现职数字台账 + 对标报告 + 回流资产数 | ⭐ **用可核验的数字谈，不用"期望年薪"谈** |

## 五、⭐ 长期主义：阶段 2 的路径（12 个月）

> ⭐ **拿到工业软件赛道的 FDE 岗位不是终点。真正的目标是 12 个月后具备跳赛道 A（AI 应用 FDE，高薪）的资格。**

| 阶段 | 时间 | 目标 | 具体动作 |
|---|---|---|---|
| **阶段 1** | 0–3 月 | 进物理 AI / 工业软件赛道 FDE | 本计划执行 |
| **阶段 2** | 3–12 月 | 用现职把 **AI 应用栈**补进真实交付 | 在交付中真做：RAG 知识库（客户规范/标准）、Agent 编排（自动化后处理与报告生成）、评测集（回归算例库）、MCP 对接（客户系统集成） |
| **阶段 3** | 12–18 月 | 带着**完整 AI 落地交付案例**跳赛道 A | ⭐ 一个"真实跑过、有失败记录、成效可量"的 AI 交付案例，胜过十个证书 |

> ⭐⭐ **阶段 2 为什么必须"在真项目里做"**：
> 因为赛道 A 的面试官问的不是"你学过 RAG 吗"，
> 而是"**你的 RAG 召回率多少、Agent 怎么防死循环、评测集怎么建的**"。
> 只有真项目能答上来。

## 六、⚠️ 三个不要

| # | 不要 | 原因 |
|---|---|---|
| 1 | ⭐ **不要在事实澄清完成前大规模投递** | 一份有硬伤的简历投 50 家 = 把同一个风险放大 50 倍 |
| 2 | **不要为了跳赛道 A 而伪造 AI 应用经验** | 面试官一问"你的 Agent 在生产环境死循环了怎么办"就穿帮，且已入职后必然暴露 |
| 3 | **不要停止现职的业绩数字采集** | ⭐ 数字只在在职时产生，离职后永远拿不到 |
