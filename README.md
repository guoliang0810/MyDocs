# MyDocs · 物理 AI × CAD/CAE 落地知识库

> **我的角色**：清航飞迈（FEMAI）**产品负责人** + **FDE（前置交付工程师）**
> **我的领域**：物理 AI 工业软件 —— AICube（物理世界引擎）、Solid（物理 AI 开发平台）、LoopAxis（行业应用平台）
> **我的战场**：航空航天（C919 复材机翼）、先进装备、智慧医疗（骨科植入物与术前规划）

---

## 这个库解决什么问题

作为 FDE，我的产出不是"文档"，而是**客户现场能不能跑起来、能不能验收、能不能沉淀回产品**。
作为产品负责人，我还要判断**该押哪条技术路线、跟谁竞争、我们的护城河是什么、钱从哪来**。

⭐ **但各维度各自最优，合起来常常是一个四不像。**
> 所以这个库是**七维 + 交叉**结构，且**分三层**：

```
┌──────────────────────────────────────────────────┐
│  【表达层】BP 叙述                                 │  ← 检验层
│  一句话/逐页结构/六个叙事装置/Q&A/Data Room/翻车案例  │     前六维能否被打包传达
└──────────────────────────────────────────────────┘
                        ↓ 检验
┌──────────┬──────────┬──────────┬──────────┐
│ 技术维度 │ 用户维度 │ 资方维度 │ 产品维度 │  ← 内容层
│ 24条路线 │ 12层画像 │ 四层估值 │ 需求闸门  │     结论与证据
├──────────┴──────────┴──────────┴──────────┤
│  【证据层】商业调研  ｜  【战术层】竞品作战        │  ← 支撑层
│  市场规模/需求验证/ICP │ Battlecard/Win-Loss/招标反推 │
└──────────────────────────────────────────────────┘
```

> **v1 → v2**：补齐 **CAD / 几何侧**。CAE 的失败有 80% 源于几何本身有缺陷。
> **v2 → v3**：补齐 **技术路线** 与 **竞品**。"物理 AI"是 **6 主线 24 子路线**，不是一样东西。
> **v3 → v4**：补齐 **用户维度** 与 **资方维度**，并新增 **交叉分析**——
> ⭐ **单维最优 ≠ 全局最优，真正的决策在各个维度打架的地方。**
> **v4 → v5**：新增 **表达层（BP 叙述）**、**证据层（商业调研）**、**战术层（竞品作战）**——
> ⭐ **BP 是检验层：一句话说不清，往往不是 BP 的问题，是问题定义的问题。**

## ⚠️ 六条硬规则

1. **编号与标准号必须核实。** 本库中每一条 arXiv 编号、标准号、报价、产品名、开源分类、
   技术路线成熟度、竞品财务数字、**用户分层数据、融资事件、估值数字**，都必须打开原始页面确认过。
   未核实的写 `⚠️未核实`，**不要凭记忆写编号**。
   ⭐ 这条规则来自两次真实教训：调研 4 个论文编号 **3 个指向完全无关的论文**；
   v3 轮调研 **18 个编号中 9 个被证伪**（含提问时给出的 DeepONet、Causal PINN、PINO 等 4 个）。
   另外还纠出：1 个标准号写错（JT 是 ISO 14306 非 14343）、2 个产品开源/商业分类错误、
   3 个竞品不存在（Aithena / Simcentrica / 涂子昕与云道智造关联）。
   完整流程见 [[100-物理AI产品与领域/000-专家作业标准-四问#五-落地为默认流程核验清单20-项]]。

2. **LLM 不产出数值。** 应力、应变、温度、寿命、重量、GCI——一切进入工程决策的数值，
   必须由确定性求解器计算。LLM 只做意图解析、代码生成、编排、解释、检索。
   详见 [[100-物理AI产品与领域/020-领域知识/LLM在物理仿真中的角色边界]]。

3. **⭐ "可执行"不等于"正确"。** LLM 生成的 CAD 代码能跑、语法合法，但几何完全错误
   （实测：IR 低至 2%，而 IoU ≈ 0）。验收标准必须用**几何内核**判定——
   B-rep 有效 → 水密 → 流形可网格化 → 量守恒 → 拓扑不变量。
   详见 [[100-物理AI产品与领域/020-领域知识/CAD与几何工程]]。

4. **没有元数据的结论不能支撑高后果决策。** 结果必须随附：求解器版本、网格、输入卡、
   材料卡、边界条件、收敛历史、GCI 研究、后处理脚本。缺了追溯链，一次交付事故就会毁掉全部信任。

5. **⭐ "物理 AI"不是一样东西，量化数字也不是一个等级。**
   - 物理 AI = **6 主线 24 子路线**，成熟度跨 4 档；选路线必须过**八条可判定硬判据**。
     见 [[100-物理AI产品与领域/020-领域知识/物理AI技术路线全景]]。
   - 任何厂商数字都要标**可核验性等级**：🅐 多源交叉 / 🅑 厂商单源+具名客户 /
     🅒 厂商口径含自证循环 / 🅓 不可核验禁止引用。见 [[100-物理AI产品与领域/030-竞品与市场/竞品地图]]。

6. **⭐ 单维最优 ≠ 全局最优。** 四个维度（技术/用户/资方/产品）各自追求自己的最优，
   合起来常常是四不像。**每个重大决策都要过一遍四维交叉**：
   - ⭐ **用户最想要的不是"算得快"，是"敢签字"**（生成仿真输入信任度仅 17%，"完全信任"≤3%）
   - ⭐ **投资人买的是"用 AI 改写过的、可被审计的确定性"**，不是 AI 概念
   - ⭐ **三维冲突时不要选边，要重定义问题**（例："AI 替代求解器" → "AI 把 CAE 迭代速度提升一个数量级"）
   - ⭐ 详见 [[100-物理AI产品与领域/000-多维交叉分析]]
