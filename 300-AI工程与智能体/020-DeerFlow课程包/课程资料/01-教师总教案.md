# 教师总教案（21天通用）

## 每天 4 节课的固定节奏（45min × 4）
### 每节课的 45 分钟配方
- 0–5：复盘 + 今日目标（用一句话）
- 5–15：概念讲解（只讲 1 个主概念 + 1 个副概念）
- 15–35：带做代码（老师领跑，学生跟打）
- 35–42：当堂练习（小题当场交付，能跑即过）
- 42–45：作业说明 + 评价标准（提交物写清楚）

### 每天的 4 节课角色分工
- 第1节：建立共同语言（概念与术语）
- 第2节：搭骨架（能跑通最小闭环）
- 第3节：加约束（错误处理/边界/抽象）
- 第4节：完成可交付（产物、测试、演示脚本）

---

## 教学目标分层（老师讲课时怎么控“深浅”）
### 课堂必须讲清楚的（不讲清楚就会崩）
- 状态机/编排思维：为什么 Agent 不是一个 while True
- 工具调用边界：工具是“安全外设”，不是“随便执行”
- 线程隔离：每个对话/线程都有自己的 workspace
- 可观测性：没有日志与事件流，就无法调试 Agent

### 课堂可以点到为止的（学生课后扩展）
- 更复杂的模型路由（多模型选择、reasoning effort）
- 容器级别隔离与资源限制（cgroup 等）
- 向量检索/embedding 与语义检索
- 前端可视化（节点图、流式消息 UI）

---

## 通用评分规则（建议每天都用）
- 必做作业：能跑 + 产物正确 + 有最小测试/自检脚本
- 选做作业：结构更清晰/更安全/更可观测/更可扩展
- 扣分常见项：无错误处理、无边界校验、日志不可读、无法复现

---

## 常见卡点与应对话术（初学者友好）
- “我看不懂 LangGraph”：先把它当成“有状态的流程图”，从 if/else + while 翻译过去
- “工具调用好绕”：先把工具当成 REST API，一次只做一件事，输入输出写清楚
- “为什么要 Sandbox”：把它当成把刀放进刀鞘里用，避免误伤系统
- “记忆怎么做”：先做最简 JSON 存事实，再做抽取和注入，最后做检索

---

## 每日授课前清单（2分钟）
- 能启动 API 服务并访问 `/health`（或等价）
- 能调用一次 LLM（返回 200，能看到请求日志）
- 学生机器环境一致（Python/Node/依赖安装完成）
- 当天模板代码已准备（在 DayXX 的“学生材料”里）

---

## 每日结课清单（2分钟）
- 当天必做作业的“提交物格式”再次强调
- 给出 1 个“加分项”方向（让进阶学生有事做）
- 留 1 个“自测问题”（让初学者知道自己是否学会）
